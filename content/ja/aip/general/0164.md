# ソフトデリート

クライアントがソフトデリートと復元機能を求める理由はいくつかあるが、最も重要な理由は一つに集約される：ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを復元することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、復元する必要がある状況に対応するため、復元する機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除して**はならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースに `state` フィールド（AIP-216）が含まれている場合、`DELETED` 状態値を含める**べきである**（should）。

### 復元（Undelete）

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能でない限り、完全に設定されたリソースを**含めるべきである**（should）。
  - 復元RPCが[長時間実行](#長時間実行の復元)である場合、レスポンスメッセージは、リソース自体に解決される `google.longrunning.Operation` **でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。それは `name` と**呼ばれるべきである**（should）。
  - フィールドは [requiredとしてアノテーション][aip-203] **されるべきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を**識別すべきである**（should）。
  - フィールドのコメントは、リソースパターンを**文書化すべきである**（should）。
- リクエストメッセージには、他の必須フィールドを含めて**はならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含めるべきではない**（should not）。

### 長時間実行の復元

一部のリソースは、通常のAPIリクエストに適切な時間よりも長い時間を要して復元される。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### 完全削除（Expunge）

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全な削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態にあるリソース（例：`delete_time`が設定されている）に対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは、:expungeサフィックスを付けたカスタムメソッドを使用**しなければならない**（must）。
- HTTP動詞はPOST**でなければならず**（must）、body句は"*"**でなければならない**（must）。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` **でなければならない**（must）。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）で**あってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` が `true` でない限り）`List`（AIP-132）レスポンスで**返されるべきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、`NOT_FOUND` エラーではなくリソースを**返すべきである**（should）。

ソフトデリートを行うAPIは、それらのリソースを完全削除するための合理的な戦略を**選択してもよい**（may）。これには、合理的な期間（例：30日）後の自動完全削除、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持が含まれる。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的クライアントフレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣った体験となる：ソフトデリートされたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むための手書きコードが必要となる。

### Errors

ユーザーがリソースへのアクセス権限を持たない場合、リソースの存否にかかわらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限はリソースの存在を確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（一度も作成されていないか、すでに完全削除されている場合）、サービスは `NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、サービスは `allow_missing` が `true` であれば成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）で**エラーとすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge` を呼び出すユーザーが、存在しないリソース（一度も作成されていないか、すでに完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するが、ready状態またはソフトデリート状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
