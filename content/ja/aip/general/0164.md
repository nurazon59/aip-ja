# ソフトデリート

クライアントがソフトデリートと復元（undelete）機能を望む理由はいくつかあるが、その中でも際立つ包括的な理由がある：ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する能力を必要とする状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは、リソースをシステムから完全に削除するのではなく、削除済みとしてマークするだけ**でなければならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を含む**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは `Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージは `google.longrunning.Operation` **でなければならず**（must）、これはリソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。これは `name` と**呼ぶべきである**（should）。
  - フィールドは [requiredとしてアノテーション付け][aip-203]**すべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を**識別すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージは、ここまたは他のAIPで説明されているものを除き、他の必須フィールドを含め**てはならず**（must not）、他のオプショナルフィールドを含める**べきではない**（should not）。

### Long-running 復元

一部のリソースは、通常のAPIリクエストに適切な時間よりも復元に長い時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCがlong-runningでない場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### 完全削除（Expunge）

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタム メソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態にあるリソース（例：`delete_time` が設定されている）に対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` 接尾辞を持つカスタム メソッドを使用しなければならない。
- HTTP動詞は `POST` でなければならず、`body` 句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### Long-running 完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除の対象となるリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` がtrueでない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す**べきである**（should）。

ソフトデリートするAPIは、妥当な期間（30日など）後の自動完全削除、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、リソースを完全削除するための合理的な戦略を選択**してもよい**（may）。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的クライアントフレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントでのエクスペリエンスが劣る：ソフトデリートされたリソースのIDは、カスタム メソッド（復元）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタム メソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、そのリソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限は、リソースの存在を確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（一度も作成されていないか、既に完全削除されている）、サービスは `NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは `allow_missing` が `true` であれば成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）でエラーに**すべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが、存在しないリソース（一度も作成されていないか、既に完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが `READY` または `SOFT_DELETED` 状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
