# ソフトデリート

クライアントがソフトデリートと復元（undelete）機能を望む理由はいくつかあるが、最も重要な理由はミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「復元」（undelete）機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマーク**しなければならない**（must）が、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されているように、`delete_time` フィールドと `purge_time` フィールドの両方を持つ**べきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を含める**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 動詞は `POST` で**なければならない**（must）。
- `body` 句は `"*"` で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - 復元 RPC が [長時間実行](#long-running-undelete) である場合、レスポンスメッセージはリソース自体に解決される `google.longrunning.Operation` で**なければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。それは `name` と呼ばれる**べきである**（should）。
  - フィールドは [required として注釈][aip-203] される**べきである**（should）。
  - フィールドは参照する [リソースタイプ][aip-123] を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージは、この AIP または他の AIP で説明されているものを除き、他の必須フィールドを含ん**ではならない**（must not）、また他のオプションフィールドを含む**べきではない**（should not）。

### 長時間実行の復元

一部のリソースの復元は、通常の API リクエストに適した時間よりも長くかかる。この状況では、API は代わりに long-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPC が長時間実行でない場合の戻り値の型）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全な削除をトリガーできるようにするために、`Expunge` カスタム メソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（つまり `delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI は :expunge サフィックスを使用するカスタム メソッドを使用しなければならない。
- HTTP 動詞は POST でなければならず、body 句は "*" でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドが存在する**べきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` が true でない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートする API は、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。これには、合理的な期間（30日など）後の自動パージ、ユーザーが有効期限（AIP-214）を設定できるようにすること、またはリソースを無期限に保持することが含まれる。どの戦略が選択されるかに関係なく、API はソフトデリートされたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいて、ハードデリートされたリソースよりも劣る体験となる。ソフトデリートされたリソースの ID は、カスタム メソッド（undelete）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタム メソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースの存在の有無に関係なく、サービスは `PERMISSION_DENIED`（HTTP 403）エラーを返さ**なければならない**（must）。権限は、リソースが存在するかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（作成されたことがないか、すでに完全削除されている場合）、サービスは `NOT_FOUND`（HTTP 404）エラーを返さ**なければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、サービスは `allow_missing` が `true` であれば成功**しなければならない**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）エラーを返す**べきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されたことがないか、すでに完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが ready 状態でもソフトデリート状態でもない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
