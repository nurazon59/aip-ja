# ソフトデリート

クライアントがソフトデリートと復元（undelete）機能を望む理由はいくつかあるが、最も重要な理由の一つが際立っている。それは、ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドは、リソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must）。このように動作する場合、`google.protobuf.Empty`ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースが`state`フィールドを含む場合、リソースは`DELETED`状態値を含む**べきである**（should）（AIP-216）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、それが実行不可能でない限り、完全に設定されたリソースを含む**べきである**（should）。
  - 復元RPCが[長時間実行](#long-running-undelete)の場合、レスポンスメッセージは`google.longrunning.Operation`で**なければならず**（must）、リソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは、次のような共通のリクエストメッセージパターンを実装する。

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。これは`name`と呼ばれる**べきである**（should）。
  - このフィールドは[必須としてアノテーションする][aip-203]**べきである**（should）。
  - このフィールドは、参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージは、他の必須フィールドを含ん**ではならず**（must not）、このAIPまたは別のAIPで説明されているものを除き、他のオプションフィールドを含む**べきではない**（should not）。

### 長時間実行復元

一部のリソースは、通常のAPIリクエストに対して適切な時間よりも長く復元に時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCが長時間実行でない場合の戻り値の型となる）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態にあるリソースに対して操作できる（例：`delete_time`が設定されている）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞は`POST`でなければならず、body句は`"*"`でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### 長時間実行完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）に**してもよい**（may）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは、次のような共通のリクエストメッセージパターンを実装する。

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）レスポンスで返される**べきではない**（should not）（`bool show_deleted`がtrueの場合を除く）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、それらのリソースを完全に削除するための合理的な戦略を選択**してもよい**（may）。これには、妥当な期間（30日など）後の自動削除、ユーザーによる有効期限設定の許可（AIP-214）、無期限の保持が含まれる。選択された戦略に関わらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいて完全削除されたリソースよりも体験が劣る。ソフトデリートされたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースの存在の有無に関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限は、リソースが存在するかどうかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（未作成または既に完全削除済み）、サービスは`NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、`allow_missing`が`true`であればサービスは成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラーに**すべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しないリソース（未作成または既に完全削除済み）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready状態でもソフトデリート状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限を要求**しなければならない**（must）（例：`<service>.<resource>.expunge`）。
