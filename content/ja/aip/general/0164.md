# ソフトデリート

クライアントがソフトデリートとアンデリートの機能を求める理由はいくつかあるが、最も重要な理由は誤操作からの回復である。アンデリートをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するために、「アンデリート」機能をサポート**してもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete` メソッドはリソースをシステムから完全に削除するのではなく、単に削除済みとしてマークし**なければならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されているように `delete_time` と `purge_time` の両方のフィールドを持つ**べきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を含める**べきである**（should）。

### アンデリート

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP verb は `POST` で**なければならない**（must）。
- `body` 句は `"*"` で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能でない限り、完全にデータが投入されたリソースを含める**べきである**（should）。
  - アンデリート RPC が [long-running](#long-running-undelete) である場合、レスポンスメッセージはリソース自体に解決される `google.longrunning.Operation` で**なければならない**（must）。

### アンデリートリクエストメッセージ

アンデリートメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。それは `name` と呼ばれる**べきである**（should）。
  - フィールドは [required としてアノテーションする][aip-203] ことを**すべきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントは、リソースパターンを文書化**すべきである**（should）。
- リクエストメッセージには他の必須フィールドを含め**てはならず**（must not）、また、本 AIP または他の AIP で説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### long-running アンデリート

一部のリソースは、通常の API リクエストとしては妥当でない時間をアンデリートにかける。この場合、API は代わりに long-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPC が long-running でなかった場合の戻り値の型）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時恒久削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して動作させることができる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP verb は `POST` で、`body` 句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### long-running Expunge

Expunge プロセスにかなりの時間がかかる場合、メソッドは `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expunge リクエストメッセージ

Expunge メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expunge されるリソースを名前で参照し**なければならない**（must）。
- その他のリクエストフィールドは存在**すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは `List`（AIP-132）レスポンスに含める**べきではない**（should not）（`bool show_deleted` が `true` の場合を除く）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND` エラーではなく）。

リソースをソフトデリートする API は、合理的な期間（30日など）後の自動パージ、ユーザーによる有効期限（AIP-214）の設定の許可、リソースの無期限保持など、リソースをパージするための合理的な戦略を選択**してもよい**（may）。どの戦略が選択されるかに関わらず、API はソフトデリートされたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣るエクスペリエンスを持つ。ソフトデリートされたリソースの ID は、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーと**しなければならない**（must）。権限は、リソースの存在確認よりも先にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない場合（作成されていないか、すでに expunge されている場合）、サービスは `NOT_FOUND`（HTTP 404）でエラーと**しなければならない**（must）。

ユーザーがソフト `Delete` を呼び出す適切な権限を持っているが、リクエストされたリソースがすでに削除されている場合、サービスは `allow_missing` が `true` の場合は成功**しなければならず**（must）、`allow_missing` が `false` の場合は `NOT_FOUND`（HTTP 404）でエラーと**すべきである**（should）。

ユーザーが `Undelete` を呼び出す適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

存在しないリソース（作成されていないか、すでに expunge されている）に対して `Expunge` を呼び出す場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが ready または soft-deleted 状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な expunge 権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
