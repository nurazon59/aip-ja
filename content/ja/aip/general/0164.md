# ソフト削除

クライアントがソフト削除と復元の機能を望む理由はいくつかあるが、最も重要な理由の1つは、ミスからの回復である。復元をサポートするサービスは、誤って削除されたリソースをユーザーが回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復が必要な状況に対応するため、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドはリソースを削除済みとしてマークするだけで、システムから完全には削除**してはならない**（must）。このメソッドがそのように動作する場合、`google.protobuf.Empty`ではなく、更新されたリソースを**返すべきである**（should）。

ソフト削除をサポートするリソースは、AIP-148で説明されている`delete_time`フィールドと`purge_time`フィールドの両方を**持つべきである**（should）。さらに、リソースが`state`フィールドを含む場合（AIP-216）、`DELETED`状態値を**含むべきである**（should）。

### 復元

ソフト削除をサポートするリソースは、`Undelete`メソッドを**提供すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスには、実行不可能な場合を除き、完全に設定されたリソースを**含めるべきである**（should）。
  - 復元RPCが[長時間実行](#長時間実行の復元)の場合、レスポンスメッセージはリソース自体に解決される`google.longrunning.Operation`**でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。これは`name`**と呼ばれるべきである**（should）。
  - フィールドは[必須としてアノテーションされるべきである][aip-203]。
  - フィールドは参照する[リソースタイプ][aip-123]を**識別すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含めるべきではない**（should not）。

### 長時間実行の復元

一部のリソースは、通常のAPIリクエストとして合理的な時間よりも長く復元にかかる。この場合、APIは代わりに長時間実行オペレーション（AIP-151）を**使用すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でない場合の戻り値の型）に**設定しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを**指定しなければならない**（must）。

### Expunge

ソフト削除をサポートするリソースは、リソースの即時完全削除をトリガーできる`Expunge`カスタムメソッドを**提供してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態（例：`delete_time`が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIでは`:expunge`サフィックス付きのカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は"*"でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### 長時間実行のexpunge

Expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）で**あってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeするリソースを名前で**参照しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### ListとGet

ソフト削除されたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）レスポンスで**返されるべきではない**（should not）。ソフト削除されたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを**返すべきである**（should）。

ソフト削除を行うAPIは、合理的な期間（30日など）後の自動パージ、ユーザーが有効期限を設定できるようにすること（AIP-214）、またはリソースを無期限に保持することなど、リソースをパージするための合理的な戦略を**選択してもよい**（may）。選択された戦略に関わらず、APIはソフト削除されたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフト削除可能なリソースは、宣言的クライアントにおいてハード削除されたリソースよりも劣る体験となる。ソフト削除されたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要となる。

### エラー

ユーザーがリソースへのアクセス権限を持たない場合、リソースの存在の有無に関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）で**エラーを返さなければならない**（must）。権限は、リソースが存在するかどうかのチェックよりも前に**チェックしなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがないか、既にexpungeされている）場合、サービスは`NOT_FOUND`（HTTP 404）で**エラーを返さなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、`allow_missing`が`true`の場合はサービスは**成功しなければならず**（must）、`allow_missing`が`false`の場合は`NOT_FOUND`（HTTP 404）で**エラーを返すべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（作成されたことがないか、既にexpungeされている）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するがreadyまたはsoft-deleted状態でない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
