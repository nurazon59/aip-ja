# ソフトデリート

クライアントがソフトデリートと復元機能を望む理由はいくつかあるが、最も重要な理由が際立っている：ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するため、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除して**はならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty` の代わりに更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time` と `purge_time` の両方のフィールドを持つ**べきである**（should）。さらに、リソースに `state` フィールド（AIP-216）が含まれる場合、リソースは `DELETED` 状態値を含む**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能でない限り、完全にデータが投入されたリソースを含める**べきである**（should）。
  - 復元RPCが[長時間実行](#長時間実行の復元)の場合、レスポンスメッセージは `google.longrunning.Operation` **でなければならず**（must）、リソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。これは `name` と**すべきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]**すべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントはリソースパターンを文書化**すべきである**（should）。
- リクエストメッセージは他の必須フィールドを含めて**はならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### 長時間実行の復元

一部のリソースは、通常のAPIリクエストに合理的な時間よりも復元に時間がかかる。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時永続的削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）**であってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` がtrueでない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、合理的な期間（30日など）後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、リソースの無期限保持など、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。選択した戦略に関わらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントでのエクスペリエンスが劣る：ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースへのアクセス権限を持たない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーと**しなければならない**（must）。権限はリソースの存在確認よりも先にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（作成されたことがないか、既に完全削除されている）、サービスは `NOT_FOUND`（HTTP 404）でエラーと**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、`allow_missing` が `true` であればサービスは成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）でエラーと**すべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されたことがないか、既に完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready状態またはソフトデリート状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求し**なければならない**（must）。
