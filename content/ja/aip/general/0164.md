# ソフトデリート

クライアントがソフトデリートおよび削除取り消し（undelete）機能を望む理由は
いくつかあるが、その中でも際立つ理由の1つは、ミスからの回復である。削除
取り消しをサポートするサービスは、ユーザーが誤って削除したリソースを回復
することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応する
ため、「削除取り消し」機能をサポート**してもよい**（may）。

リソースが削除取り消しをサポートする必要がある場合、`Delete` メソッドは単に
リソースを削除済みとしてマークするだけで、システムから完全に削除し**ては
ならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty`
の代わりに更新後のリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、
`delete_time` と `purge_time` の両方のフィールドを持つ**べきである**（should）。
さらに、リソースに `state` フィールド（AIP-216）が含まれる場合、`DELETED`
状態値を含める**べきである**（should）。

### 削除取り消し

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべき
である**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。
  `UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを含める
    **べきである**（should）。
  - 削除取り消しRPCが[長時間実行](#長時間実行の削除取り消し)である場合、
    レスポンスメッセージはリソース自体に解決される
    `google.longrunning.Operation` **でなければならない**（must）。

### 削除取り消しリクエストメッセージ

削除取り消しメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。`name` と呼ぶ
  **べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]**されるべきである**
    （should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**
    （should）。
  - フィールドのコメントはリソースパターンを文書化**すべきである**（should）。
- リクエストメッセージには他の必須フィールドを含め**てはならず**（must not）、
  本AIPまたは他のAIPで説明されているものを除き、他のオプションフィールドを
  含める**べきではない**（should not）。

### 長時間実行の削除取り消し

一部のリソースは、通常のAPIリクエストでは妥当でないほど削除取り消しに時間が
かかる。この状況では、APIは代わりに長時間実行操作（AIP-151）を使用**すべき
である**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でない場合の戻り値の型）に設定
  **しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを指定
  **しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全削除を
トリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。
このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態
（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` サフィックスを持つカスタムメソッドを使用
  **しなければならない**（must）。
- HTTP動詞は `POST` **でなければならず**（must）、body句は `"*"` **でなければ
  ならない**（must）。
- レスポンスメッセージは `google.protobuf.Empty` または
  `google.longrunning.Operation` **でなければならない**（must）。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに
`google.longrunning.Operation`（AIP-151）**であってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照
  **しなければならない**（must）。
- 他のリクエストフィールドを設ける**べきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは
（`bool show_deleted` がtrueの場合を除き）`List`（AIP-132）レスポンスで返す
**べきではない**（should not）。ソフトデリートされたリソースに対する
`Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す
**べきである**（should）。

ソフトデリートを行うAPIは、合理的な期間（30日など）後の自動削除、ユーザーに
よる有効期限（AIP-214）の設定許可、リソースの無期限保持など、リソースを
削除するための合理的な戦略を選択**してもよい**（may）。どの戦略が選択されるに
せよ、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化
**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリート
されたリソースよりも劣った体験となる：ソフトデリートされたリソースのIDは、
カスタムメソッド（削除取り消し）が呼び出されない限り再利用できないため、
命令的クライアントを導入するか、カスタムメソッドの使用を組み込むための
手書きコードが必要となる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、リソースが存在するか
どうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラー
**にしなければならない**（must）。権限はリソースの存在確認に先立って
チェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない
場合（作成されなかったか、既に完全削除されている）、サービスは
`NOT_FOUND`（HTTP 404）でエラー**にしなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、リクエスト
されたリソースが既に削除されている場合、サービスは `allow_missing` が
`true` の場合は成功**しなければならず**（must）、`allow_missing` が `false` の
場合は `NOT_FOUND`（HTTP 404）でエラー**にすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、リクエストされた
リソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で
応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しない（作成されなかったか、既に完全削除
されている）リソースをリクエストした場合、メソッドは `NOT_FOUND`
（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが ready 状態でもソフトデリート状態でもない場合、メソッドは
`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除
権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求
**しなければならない**（must）。
