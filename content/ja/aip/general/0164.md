# ソフトデリート

クライアントがソフトデリートと復元機能を望む理由はいくつかあるが、最も重要な理由はミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するため、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく更新されたリソースを**返すべきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように`delete_time`フィールドと`purge_time`フィールドの両方を**持つべきである**（should）。さらに、リソースに`state`フィールド（AIP-216）が含まれている場合、リソースは`DELETED`状態値を含める**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスには、実行不可能でない限り、完全にデータが投入されたリソースを含める**べきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)の場合、レスポンスメッセージはリソース自体に解決される`google.longrunning.Operation`**でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。`name`と呼ぶ**べきである**（should）。
  - フィールドには[requiredとしてアノテーション][aip-203]を付ける**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージには、これ以外の必須フィールドを含め**てはならず**（must not）、これまたは別のAIPで説明されているもの以外のオプションフィールドを含める**べきではない**（should not）。

### long-runningな復元

一部のリソースでは、復元に通常のAPIリクエストとして妥当な時間よりも長くかかる場合がある。この状況では、APIは代わりにlong-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCがlong-runningでなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`フィールドと`metadata_type`フィールドの両方を指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガできる`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態（例：`delete_time`が設定されている）にあるリソースに対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は"*"でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### long-runningな完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）**であってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）レスポンスで**返されるべきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを**返すべきである**（should）。

リソースをソフトデリートするAPIは、妥当な期間（30日など）後の自動完全削除、ユーザーが有効期限を設定できるようにする方法（AIP-214）、リソースを無期限に保持する方法など、リソースを完全削除するための合理的な戦略を選択**してもよい**（may）。選択された戦略にかかわらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントでの体験が劣る：ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、そのリソースが存在するかどうかにかかわらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラー**としなければならない**（must）。権限は、リソースの存在を確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（一度も作成されていないか、既に完全削除されている場合）、サービスは`NOT_FOUND`（HTTP 404）でエラー**としなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、`allow_missing`が`true`であればサービスは成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）で**エラーとすべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しないリソース（一度も作成されていないか、既に完全削除されている）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するがready状態でもソフトデリート状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
