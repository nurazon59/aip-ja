# ソフトデリート

クライアントがソフトデリートと復元の機能を望む理由はいくつかあるが、その中でも特に重要な理由は、ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、復元の機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドは、リソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく、更新されたリソースを**返すべきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`と`purge_time`の両方のフィールドを**持つべきである**（should）。さらに、リソースが`state`フィールド（AIP-216）を含む場合、`DELETED`状態値を**含めるべきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`節は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスには、実行不可能でない限り、完全に設定されたリソースを**含めるべきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージは`google.longrunning.Operation`**でなければならず**（must）、リソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。`name`と呼**ばれるべきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]**すべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントにはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージには、これ以外の必須フィールドを含めて**はならず**（must not）、本AIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含めるべきではない**（should not）。

### Long-running 復元

一部のリソースでは、通常のAPIリクエストに適切な時間よりも長く復元に時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を**使用すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプは、リソース（RPCがlong-runningでなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全な削除をトリガーできるようにする`Expunge`カスタム メソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態（例：`delete_time`が設定されている）のリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを付けたカスタム メソッドを**使用しなければならない**（must）。
- HTTP動詞は`POST`**でなければならず**（must）、body節は`"*"`**でなければならない**（must）。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`**でなければならない**（must）。

### Long-running expunge

expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）に**してもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、名前によってexpungeするリソースを参照**しなければならない**（must）。
- これ以外のリクエストフィールドは存在**すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）のレスポンスに返さ**れるべきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを**返すべきである**（should）。

リソースをソフトデリートするAPIは、それらのリソースをパージするための合理的な戦略を**選択してもよい**（may）。例えば、合理的な期間（30日間など）経過後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持などがある。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験となる。ソフトデリートされたリソースのIDは、カスタム メソッド（undelete）が呼ばれない限り再利用できないため、命令型クライアントを導入するか、カスタム メソッドの使用を組み込むために手書きのコードが必要となる。

### エラー

リソースの存在有無に関わらず、ユーザーがリソースにアクセスする権限を持たない場合、サービスは`PERMISSION_DENIED`（HTTP 403）でエラー**しなければならない**（must）。権限は、リソースが存在するかどうかを確認する前に**チェックしなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（作成されていないか既にexpungeされている場合）、サービスは`NOT_FOUND`（HTTP 404）でエラー**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは`allow_missing`が`true`の場合は**成功しなければならず**（must）、`allow_missing`が`false`の場合は`NOT_FOUND`（HTTP 404）で**エラーすべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しない（作成されていないか既にexpungeされている）リソースを要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するがready状態でもソフトデリート状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
