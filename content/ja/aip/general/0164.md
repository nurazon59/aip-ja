# ソフトデリート

クライアントがソフトデリートと復元機能を望む理由はいくつかあるが、最も重要な理由の1つは**誤操作からの回復**である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復機能が必要な状況に対応するため、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除しては**ならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを**返すべきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている `delete_time` フィールドと `purge_time` フィールドの両方を**持つべきである**（should）。さらに、リソースに `state` フィールド（AIP-216）が含まれる場合、リソースは `DELETED` ステート値を**含めるべきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete` メソッドを**提供すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソースそのもの**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能な場合を除き、完全に設定されたリソースを**含めるべきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージはリソースそのものに解決される `google.longrunning.Operation` **でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。これは `name` と**呼ぶべきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]を**付けるべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を**特定すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージには他の必須フィールドを**含めてはならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含めるべきではない**（should not）。

### Long-running 復元

一部のリソースは、通常のAPIリクエストに適した時間よりも復元に長い時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を**使用すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCがlong-runningでない場合の戻り値の型）に**設定しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを**指定しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがready状態またはソフトデリートされたリソースの即時完全削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態にあるリソース（例：`delete_time` が設定されている）に対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` サフィックスを持つカスタムメソッドを**使用しなければならない**（must）。
- HTTP動詞は `POST` **でなければならず**（must）、`body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` **でなければならない**（must）。

### Long-running 完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）で**あってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で**参照しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは `List`（AIP-132）レスポンスで**返されるべきではない**（should not）（`bool show_deleted` が `true` の場合を除く）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、`NOT_FOUND` エラーではなくリソースを**返すべきである**（should）。

ソフトデリートリソースのAPIは、合理的な期間（30日など）経過後の自動削除、ユーザーが有効期限を設定できるようにする（AIP-214）、またはリソースを無期限に保持するなど、それらのリソースを削除するための合理的な戦略を**選択してもよい**（may）。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験となる。ソフトデリートされたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要となる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、リソースの存在有無に関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）で**エラーとしなければならない**（must）。権限はリソースの存在確認よりも**前にチェックしなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（一度も作成されていないか、既に完全削除されている場合）、サービスは `NOT_FOUND`（HTTP 404）で**エラーとしなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは `allow_missing` が `true` の場合は**成功しなければならず**（must）、`allow_missing` が `false` の場合は `NOT_FOUND`（HTTP 404）で**エラーとすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge` を呼び出すユーザーが、存在しないリソース（一度も作成されていないか、既に完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するが、ready状態またはソフトデリート状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限を**要求しなければならない**（must）（例：`<service>.<resource>.expunge`）。
