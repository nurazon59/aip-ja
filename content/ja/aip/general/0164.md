# ソフトデリート

クライアントがソフトデリートと復元機能を求める理由はいくつかあるが、最も重要な理由は「誤りからの回復」である。復元をサポートするサービスでは、ユーザーが誤って削除したリソースを復旧できるようになる。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、復元機能が必要になる状況に対応するために、「復元」（undelete）機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドは、リソースをシステムから完全に削除せず、単に削除済みとしてマーク**しなければならない**（must）。そのように動作する場合、`google.protobuf.Empty`ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースが`state`フィールド（AIP-216）を含む場合、`DELETED`状態値を含める**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）:

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソースそのもので**なければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージは`google.longrunning.Operation`で**なければならない**（must）。このOperationはリソースそのものに解決される。

### 復元リクエストメッセージ

復元メソッドは、共通のリクエストメッセージパターンを実装する:

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドが含まれ**なければならない**（must）。その名前は`name`と**すべきである**（should）。
  - フィールドは[必須としてアノテーション][aip-203]される**べきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントは、リソースパターンを記載する**べきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならない**（must not）。また、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### 長時間実行される復元

一部のリソースでは、復元に通常のAPIリクエストとしては妥当でない時間がかかる。このような状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）:

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンス型は、リソース（RPCがlong-runningでなかった場合の戻り値の型）に設定され**なければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドが指定され**なければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、`SOFT_DELETED`のいずれかの状態（例：`delete_time`が設定されている）のリソースに対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは:expungeサフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞はPOST、body句は"*"でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### 長時間実行される完全削除

完全削除処理にかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）**であってもよい**（may）:

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは、共通のリクエストメッセージパターンを実装する:

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドが存在する**べきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueの場合を除き）`List`（AIP-132）のレスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND`エラーではなく）。

ソフトデリートを行うAPIは、合理的な期間（30日など）経過後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持を含む、リソースのパージに関する合理的な戦略を選択**してもよい**（may）。どの戦略を選択した場合でも、APIは、ソフトデリートされたリソースが完全に削除されるタイミングを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも使い勝手が悪い。ソフトデリートされたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、リソースの存在有無にかかわらず、サービスは`PERMISSION_DENIED`（HTTP 403）エラーを返さ**なければならない**（must）。権限は、リソースの存在確認よりも先にチェックされ**なければならない**（must）。

ユーザーが適切な権限を持つが、要求されたリソースが存在しない（作成されたことがない、または既に完全削除されている）場合、サービスは`NOT_FOUND`（HTTP 404）エラーを返さ**なければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持つが、要求されたリソースが既に削除されている場合、サービスは、`allow_missing`が`true`であれば成功**しなければならない**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）エラーを返す**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持つが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しない（作成されたことがない、または既に完全削除された）リソースを要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、`CREATING`、`READY`、`SOFT_DELETED`のいずれの状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別個の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
