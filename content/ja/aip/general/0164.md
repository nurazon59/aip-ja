# ソフト削除

クライアントがソフト削除および復元（undelete）機能を望む理由はいくつかあるが、最も包括的な理由の一つが際立っている。それはミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「復元」（undelete）機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは、単にリソースを削除済みとしてマーク**しなければならず**（must）、システムから完全に削除しない。このメソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを返す**べきである**（should）。

ソフト削除をサポートするリソースは、AIP-148で説明されているように、`delete_time` と `purge_time` の両方のフィールドを持つ**べきである**（should）。さらに、リソースに `state` フィールドが含まれる場合（AIP-216）、リソースは `DELETED` 状態値を含める**べきである**（should）。

### Undelete

ソフト削除をサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` で**なければならない**（must）。
- `body` 句は `"*"` で**なければならない**（must）。
- レスポンスメッセージはリソースそのもので**なければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能な場合を除き、完全にデータが投入されたリソースを含める**べきである**（should）。
  - 復元RPCが[長時間実行](#long-running-undelete)である場合、レスポンスメッセージは `google.longrunning.Operation` で**なければならず**（must）、これはリソースそのものに解決される。

### Undelete リクエストメッセージ

Undeleteメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。このフィールドは `name` と呼ぶ**べきである**（should）。
  - フィールドは[必須としてアノテーション付け][aip-203]**すべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントはリソースパターンを文書化**すべきである**（should）。
- リクエストメッセージは、他の必須フィールドを含め**てはならず**（must not）、本AIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### 長時間実行の Undelete

一部のリソースは、通常のAPIリクエストに適した時間よりも復元に時間がかかる。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でなかった場合の戻り型）に設定**しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフト削除をサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞は `POST` でなければならず、`body` 句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### 長時間実行の Expunge

Expungeプロセスに大きな時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）に**してもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expunge リクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、消去するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドを含める**べきではない**（should not）。

### List と Get

ソフト削除されたリソースは、デフォルトでは（`bool show_deleted` が true でない限り）`List`（AIP-132）レスポンスに返される**べきではない**（should not）。ソフト削除されたリソースに対する `Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND` エラーではなく）。

リソースをソフト削除するAPIは、合理的な期間（30日など）後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、リソースの無期限保持など、リソースをパージするための合理的な戦略を選択**してもよい**（may）。どの戦略を選択するかにかかわらず、APIはソフト削除されたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフト削除可能なリソースは、宣言的クライアントにおいてハード削除されたリソースよりも劣った体験となる。ソフト削除されたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

リソースが存在するかどうかにかかわらず、ユーザーがリソースにアクセスする権限を持たない場合、サービスは `PERMISSION_DENIED`（HTTP 403）エラーを返さ**なければならない**（must）。権限は、リソースが存在するかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（作成されていないか、すでに消去されている）、サービスは `NOT_FOUND`（HTTP 404）エラーを返さ**なければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、`allow_missing` が `true` であればサービスは成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）エラーを返す**べきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが、存在しないリソース（作成されていないか、すでに消去されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready またはソフト削除された状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別の明示的な消去権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
