# ソフトデリート

クライアントがソフトデリートとundelete機能を望む理由はいくつかあるが、最も重要な理由はミスからの回復である。undeleteをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するため、"undelete"機能をサポート**してもよい**（may）。

リソースがundeleteをサポートする必要がある場合、`Delete`メソッドは単にリソースを削除済みとしてマーク**しなければならない**（must）が、システムから完全に削除してはならない。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`フィールドと`purge_time`フィールドの両方を持つ**べきである**（should）。さらに、リソースが`state`フィールドを含む場合（AIP-216）、`DELETED`状態値を含める**べきである**（should）。

### Undelete

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソースそのもので**なければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - undelete RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージは、リソースそのものに解決される`google.longrunning.Operation`で**なければならない**（must）。

### Undeleteリクエストメッセージ

Undeleteメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。`name`と命名する**べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]される**べきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンをドキュメント化する**べきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならない**（must not）、また、このAIPや他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### Long-running undelete

リソースのundeleteに通常のAPIリクエストとして妥当な時間よりも長くかかる場合がある。このような状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCがlong-runningでない場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`フィールドと`metadata_type`フィールドの両方を指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全な削除をトリガーできるようにするために、`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態（例：`delete_time`が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは:expungeサフィックスを使用するカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は`"*"`でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### Long-running expunge

expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに長時間実行オペレーション`google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeするリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドが存在**すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、合理的な時間（30日など）後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。どの戦略が選択されるかに関係なく、APIはソフトデリートされたリソースがいつ完全に削除されるかをドキュメント化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣った体験となる。ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、そのリソースが存在するかどうかに関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラーと**しなければならない**（must）。権限は、リソースの存在を確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない（作成されたことがないか、既にexpungeされている）場合、サービスは`NOT_FOUND`（HTTP 404）でエラーと**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが既に削除されている場合、`allow_missing`が`true`であればサービスは成功**しなければならない**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラーとす**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しない（作成されたことがないか、既にexpungeされている）リソースをリクエストした場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready状態またはソフトデリート状態でない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的なパーミッションエラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除パーミッションとは別の明示的なexpungeパーミッション（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
