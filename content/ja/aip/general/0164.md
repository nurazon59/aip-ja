# ソフトデリート

クライアントがソフトデリートと復元機能を望む理由はいくつかあるが、最も重要な理由の1つは、ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドは単にリソースが削除されたとマークするだけで、システムから完全に削除し**てはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている`delete_time`フィールドと`purge_time`フィールドの両方を**持つべきである**（should）。さらに、リソースに`state`フィールド（AIP-216）が含まれている場合、`DELETED`状態値を含める**べきである**（should）。

### Undelete

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスには、実行不可能でない限り、完全に埋められたリソースを含める**べきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)の場合、レスポンスメッセージは`google.longrunning.Operation`**でなければならず**（must）、これはリソース自体に解決される。

### Undeleteリクエストメッセージ

Undeleteメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。`name`と呼ぶ**べきである**（should）。
  - フィールドには[requiredのアノテーションを付ける][aip-203]**べきである**（should）。
  - フィールドは参照する[リソース型][aip-123]を特定する**べきである**（should）。
  - フィールドのコメントにはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージには、このAIPや他のAIPで説明されているものを除き、他の必須フィールドを含め**てはならず**（must not）、他のオプショナルフィールドを含める**べきではない**（should not）。

### long-running Undelete

一部のリソースは、通常のAPIリクエストに適切な時間よりも長く復元に時間がかかる場合がある。この状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンス型はリソースに設定**しなければならない**（must）（RPCがlong-runningでなかった場合の戻り値の型）。
- `response_type`フィールドと`metadata_type`フィールドの両方を指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態（例：`delete_time`が設定されている）のリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは:expungeサフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は"*"でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### long-running Expunge

Expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）**であってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeするリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドがあっ**てはならない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）レスポンスで返される**べきではない**（should not）（`bool show_deleted`がtrueの場合を除く）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND`エラーではなく）。

ソフトデリートを行うAPIは、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。これには、妥当な期間（例：30日）後の自動パージ、ユーザーが有効期限（AIP-214）を設定できるようにすること、またはリソースを無期限に保持することが含まれる。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験をもたらす：ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラー**しなければならない**（must）。権限は、リソースが存在するかどうかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがない、またはすでにexpungeされた）場合、サービスは`NOT_FOUND`（HTTP 404）でエラー**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、`allow_missing`が`true`であればサービスは成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラーにする**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（作成されたことがない、またはすでにexpungeされた）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、readyまたはsoft-deleted状態でない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
