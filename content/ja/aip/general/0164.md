# ソフトデリート

クライアントがソフトデリートとアンデリートの機能を望む理由はいくつかあるが、最も重要な理由は「ミスからの回復」である。アンデリートをサポートするサービスは、誤って削除されたリソースをユーザーが回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するため、「アンデリート」する機能をサポートし**てもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete`メソッドは単にリソースを削除済みとしてマークし、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`の代わりに更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースに`state`フィールド（AIP-216）が含まれている場合、リソースは`DELETED`状態値を含める**べきである**（should）。

### アンデリート

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - アンデリートRPCが[長時間実行](#long-running-undelete)の場合、レスポンスメッセージは`google.longrunning.Operation`**でなければならず**（must）、リソース自体に解決される。

### アンデリートリクエストメッセージ

アンデリートメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。これは`name`と呼ぶ**べきである**（should）。
  - フィールドは[必須としてアノテーションされる][aip-203]**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージには他の必須フィールドを含めて**はならず**（must not）、本AIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### 長時間実行アンデリート

一部のリソースは、通常のAPIリクエストに適した時間よりも長い時間をアンデリートに要する。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を使用する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でない場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーが準備完了状態またはソフトデリート状態のリソースの即時完全削除をトリガーできるようにする`Expunge`カスタム メソッドを提供し**てもよい**（may）。このメソッドは、現在準備完了状態またはソフトデリート状態にあるリソース（例：`delete_time`が設定されている）に対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを持つカスタム メソッドを使用しなければならない。
- HTTP動詞は`POST`でなければならず、`body`句は`"*"`でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### 長時間実行Expunge

expungeプロセスに大幅な時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeするリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドがある**べきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）レスポンスで返される**べきではない**（should not）（`bool show_deleted`がtrueの場合を除く）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND`エラーではなく）。

ソフトデリートを行うAPIは、妥当な期間（30日など）後の自動パージ、ユーザーによる有効期限の設定の許可（AIP-214）、リソースの無期限保持など、それらのリソースをパージするための合理的な戦略を選択し**てもよい**（may）。どの戦略が選択されるかに関わらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントでのエクスペリエンスが劣る：ソフトデリートされたリソースのIDは、カスタム メソッド（アンデリート）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタム メソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースの存在の有無にかかわらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限は、リソースの存在を確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されていないか、すでにexpungeされている）場合、サービスは`NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、サービスは`allow_missing`が`true`の場合は成功**しなければならず**（must）、`allow_missing`が`false`の場合は`NOT_FOUND`（HTTP 404）でエラーに**すべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（作成されていないか、すでにexpungeされている）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが準備完了状態でもソフトデリート状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
