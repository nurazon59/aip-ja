# ソフトデリート

クライアントがソフトデリートおよび復元（undelete）機能を望む理由はいくつかあるが、最も包括的な理由は「ミスからの回復」である。復元をサポートするサービスは、誤って削除されたリソースをユーザーが回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するために「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除してはならない。このように動作する場合、メソッドは `google.protobuf.Empty` ではなく更新後のリソースを**返すべきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を**含むべきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを**含むべきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)の場合、レスポンスメッセージはリソース自体に解決される `google.longrunning.Operation` **でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。`name` と呼ぶ**べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]する**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントはリソースパターンを文書化**すべきである**（should）。
- リクエストメッセージに他の必須フィールドを含めて**はならず**（must not）、このAIPまたは別のAIPで説明されているものを除き、他のオプショナルフィールドを含め**るべきではない**（should not）。

### Long-running undo

一部のリソースは、通常のAPIリクエストとしては妥当でないほど復元に時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCがlong-runningでなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、リソースの即時永続的削除をトリガーするための `Expunge` カスタム メソッドを提供**してもよい**（may）。このメソッドは現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは :expunge 接尾辞を持つカスタム メソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は "*" でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### Long-running expunge

expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは名前でexpungeするリソースを**参照しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは `List`（AIP-132）レスポンスで**返されるべきではない**（should not）（`bool show_deleted` がtrueの場合を除く）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、リソースを**返すべきである**（should）（`NOT_FOUND` エラーではなく）。

ソフトデリートするAPIは、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。これには、適切な期間（30日など）後の自動パージ、ユーザーが有効期限（AIP-214）を設定できるようにすること、またはリソースを無期限に保持することが含まれる。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントでの体験が劣る。ソフトデリートされたリソースのIDは、カスタム メソッド（復元）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタム メソッドの使用を組み込む手書きコードが必要となる。

### エラー

ユーザーがリソースへのアクセス権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）で**エラーとしなければならない**（must）。権限は、リソースが存在するかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがないか、既にexpungeされた）場合、サービスは `NOT_FOUND`（HTTP 404）で**エラーとしなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除済みである場合、サービスは `allow_missing` が `true` であれば**成功しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）で**エラーとすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されたことがない、または既にexpungeされた）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するがready状態でもsoft-deleted状態でもない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
