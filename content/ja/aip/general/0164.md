# ソフトデリート

クライアントがソフトデリートと復元機能を望む理由はいくつかあるが、その中でも際立った理由が1つある：ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するため、復元機能を**サポートしてもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを**返すべきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されている `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、`DELETED` 状態値を**含めるべきである**（should）。

### 復元

ソフトデリートをサポートするリソースは `Undelete` メソッドを**提供すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能な場合を除き、完全に設定されたリソースを**含めるべきである**（should）。
  - 復元 RPC が[長時間実行](#長時間実行の復元)である場合、レスポンスメッセージは `google.longrunning.Operation` **でなければならず**（must）、リソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。これは `name` と**呼ぶべきである**（should）。
  - フィールドは [required としてアノテーションされるべきである][aip-203]。
  - フィールドは参照する[リソースタイプ][aip-123]を**識別すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージは他の必須フィールドを**含めてはならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含めるべきではない**（should not）。

### 長時間実行の復元

一部のリソースでは復元に通常のAPIリクエストとして妥当な時間よりも長くかかる場合がある。この状況では、API は代わりに長時間実行オペレーション（AIP-151）を**使用すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPC が長時間実行でなかった場合の戻り値の型）に**設定しなければならない**（must）。
- `response_type` と `metadata_type` の両方のフィールドを**指定しなければならない**（must）。

### 完全削除（Expunge）

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタムメソッドを**提供してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して**操作してもよい**（may）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI は `:expunge` サフィックスを持つカスタムメソッドを**使用しなければならない**（must）。
- HTTP 動詞は `POST` **でなければならず**（must）、`body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` **でなければならない**（must）。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）で**あってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは完全削除対象のリソースを名前で**参照しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` が true の場合を除き）`List`（AIP-132）レスポンスで**返されるべきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを**返すべきである**（should）。

リソースをソフトデリートする API は、妥当な期間（30日など）後の自動削除、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、それらのリソースを削除するための合理的な戦略を**選択してもよい**（may）。選択された戦略に関わらず、API はソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的クライアント向けリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験となる：ソフトデリートされたリソースの ID は、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令型クライアントの導入やカスタムメソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラー**としなければならない**（must）。権限はリソースの存在確認よりも**前にチェックされなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（作成されたことがないか、既に完全削除されている場合）、サービスは `NOT_FOUND`（HTTP 404）でエラー**としなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、`allow_missing` が `true` であればサービスは**成功しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）で**エラーとすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されたことがないか、既に完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するが ready 状態でもソフトデリート状態でもない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
