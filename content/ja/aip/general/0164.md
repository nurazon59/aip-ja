# ソフトデリート

クライアントがソフトデリートと復元の機能を望む理由はいくつかあるが、すべてに共通する最も重要な理由は「誤りからの回復」である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを復旧することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、復旧する機能が必要な状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドはリソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースが`state`フィールド（AIP-216）を含む場合、リソースは`DELETED`状態値を含む**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスには、完全にデータが設定されたリソースを含める**べきである**（should）。ただし、それが実行不可能な場合は除く。
  - 復元RPCが[長時間実行](#長時間実行の復元)である場合、レスポンスメッセージは`google.longrunning.Operation`**でなければならず**（must）、これはリソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。これは`name`と呼称**すべきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]される**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントはリソースパターンを文書化**すべきである**（should）。
- リクエストメッセージは他の必須フィールドを含め**てはならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含め**るべきではない**（should not）。

### 長時間実行の復元

一部のリソースは、通常のAPIリクエストでは合理的でない時間を要して復元される。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態にあるリソース（例：`delete_time`が設定されている）に対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`接尾辞を持つカスタムメソッドを使用**しなければならない**（must）。
- HTTP動詞は`POST`**でなければならず**（must）、`body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`**でなければならない**（must）。

### 長時間実行のExpunge

expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）**であってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expunge対象のリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールド**は存在すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを返す**べきである**（should）。

ソフトデリートを行うAPIは、合理的な期間（30日など）後の自動削除、ユーザーによる有効期限の設定（AIP-214）の許可、リソースの無期限保持など、それらのリソースを削除するための合理的な戦略を選択**してもよい**（may）。選択される戦略に関わらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣るエクスペリエンスを持つ。ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースへのアクセス権限を持たない場合、そのリソースの存在有無にかかわらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラー**にしなければならない**（must）。権限はリソースの存在確認よりも先にチェック**しなければならない**（must）。

ユーザーが適切な権限を持つが、要求されたリソースが存在しない場合（作成されたことがないか、既にexpungeされた場合）、サービスは`NOT_FOUND`（HTTP 404）でエラー**にしなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持つが、要求されたリソースが既に削除されている場合、`allow_missing`が`true`であればサービスは成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラーと**すべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持つが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（作成されたことがないか、既にexpungeされた）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready状態でもソフトデリート状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別の明示的なexpunge権限を要求**しなければならない**（must）（例：`<service>.<resource>.expunge`）。
