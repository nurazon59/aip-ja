# ソフトデリート

クライアントがソフトデリートとアンデリート機能を望む理由はいくつかあるが、最も重要な理由の一つが際立っている。それは、ミスからの回復である。アンデリートをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「アンデリート」機能をサポート**してもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete`メソッドは、単にリソースを削除済みとしてマーク**しなければならず**（must）、システムから完全に削除してはならない。このように動作する場合、`google.protobuf.Empty`ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースが`state`フィールド（AIP-216）を含む場合、`DELETED`状態値を含める**べきである**（should）。

### アンデリート

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse`は存在しない。
  - 実行不可能でない限り、レスポンスには完全に埋められたリソースを含める**べきである**（should）。
  - アンデリートRPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージはリソース自体に解決される`google.longrunning.Operation`で**なければならない**（must）。

### アンデリートリクエストメッセージ

Undeleteメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。これは`name`と呼ばれる**べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]される**べきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントには、リソースパターンを記載する**べきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならない**（must not）。また、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### long-runningアンデリート

一部のリソースでは、通常のAPIリクエストに適した時間よりもアンデリートに時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプは、リソース（RPCがlong-runningでなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態（例：`delete_time`が設定されている）にあるリソースに対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは、:expunge接尾辞を持つカスタムメソッドを使用しなければならない。
- HTTP動詞はPOST、body句は`"*"`でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### long-running完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在する**べきではない**（should not）。

### ListとGet

ソフト削除されたリソースは、デフォルトでは`List`（AIP-132）レスポンスに返される**べきではない**（should not）（`bool show_deleted`がtrueの場合を除く）。ソフト削除されたリソースに対する`Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND`エラーではなく）。

リソースをソフト削除するAPIは、適切な期間（30日など）後の自動パージ、ユーザーによる有効期限の設定の許可（AIP-214）、またはリソースの無期限保持など、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。どの戦略が選択されるかにかかわらず、APIはソフト削除されたリソースが完全に削除される時期を文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフト削除可能なリソースは、宣言的クライアントにおいてハード削除されたリソースよりも劣ったエクスペリエンスを持つ。ソフト削除されたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、リソースが存在するかどうかにかかわらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラーと**しなければならない**（must）。権限は、リソースが存在するかを確認するよりも前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない（作成されたことがないか、すでに完全削除されている）場合、サービスは`NOT_FOUND`（HTTP 404）でエラーと**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースがすでに削除されている場合、サービスは、`allow_missing`が`true`であれば成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラーとす**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しないリソース（作成されたことがないか、すでに完全削除されている）をリクエストした場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready状態またはソフト削除状態にない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
