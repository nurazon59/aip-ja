# ソフトデリート

クライアントがソフトデリートと復元（undelete）機能を望む理由はいくつかあるが、最も重要な理由の一つが際立っている：ミスからの回復である。復元をサポートするサービスは、誤って削除されたリソースをユーザーが回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するため、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドはリソースを削除済みとしてマークするだけで、システムから完全に削除して**はならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を**含めるべきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete` メソッドを**提供すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを**含めるべきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージは `google.longrunning.Operation` **でなければならず**（must）、これはリソース自体に解決される。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。`name` と**呼ぶべきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]**すべきである**（should）。
  - フィールドは参照する[リソース型][aip-123]を**識別すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージは他の必須フィールドを**含めてはならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含めるべきではない**（should not）。

### long-runningな復元

一部のリソースは、通常のAPIリクエストとして妥当な時間よりも長い時間を復元に要する。この状況では、APIは代わりにlong-running operation（AIP-151）を**使用すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンス型はリソースに**設定しなければならない**（must）（RPCがlong-runningでない場合の戻り値の型）。
- `response_type` と `metadata_type` の両方のフィールドを**指定しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全な削除をトリガーできるようにする `Expunge` カスタムメソッドを**提供してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` 接尾辞を持つカスタムメソッドを使わなければならない。
- HTTP動詞はPOSTでなければならず、body句は「*」でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### long-runningな完全削除

完全削除プロセスに大幅な時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）で**あってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドを**含めるべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは `List`（AIP-132）レスポンスに**返されるべきではない**（should not）（`bool show_deleted` がtrueの場合を除く）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、`NOT_FOUND` エラーではなくリソースを**返すべきである**（should）。

リソースをソフトデリートするAPIは、合理的な期間（30日など）後の自動完全削除、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、それらのリソースを完全削除するための合理的な戦略を**選択してもよい**（may）。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的クライアント向けリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験を持つ。ソフトデリートされたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、そのリソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）で**エラーにしなければならない**（must）。権限は、リソースの存在確認より**前にチェックしなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがないか、既に完全削除されている）場合、サービスは `NOT_FOUND`（HTTP 404）で**エラーにしなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは `allow_missing` が `true` であれば**成功しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）で**エラーにすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されたことがないか、既に完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するが ready または soft-deleted 状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
