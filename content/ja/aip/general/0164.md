# ソフトデリート

クライアントがソフトデリートとアンデリートの機能を望む理由はいくつかあるが、一つの包括的な理由が際立っている：ミスからの回復である。アンデリートをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「アンデリート」する機能をサポート**してもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete`メソッドは、単にリソースを削除済みとしてマークし、システムから完全に削除し**ないこと**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているとおり、`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースに`state`フィールドが含まれる場合（AIP-216）、リソースは`DELETED`状態値を含める**べきである**（should）。

### Undelete

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`と**しなければならない**（must）。
- `body`句は`"*"`と**しなければならない**（must）。
- レスポンスメッセージはリソース自体と**しなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - Undelete RPCが[長時間実行](#長時間実行のundelete)の場合、レスポンスメッセージは`google.longrunning.Operation`と**しなければならず**（must）、リソース自体に解決される。

### Undeleteリクエストメッセージ

Undeleteメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。これは`name`と呼ばれる**べきである**（should）。
  - フィールドは[requiredとしてアノテーションされる][aip-203]**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージは他のrequiredフィールドを含んでは**ならず**（must not）、またこのAIPまたは別のAIPで説明されているもの以外のoptionalフィールドを含む**べきではない**（should not）。

### 長時間実行のUndelete

一部のリソースは、通常のAPIリクエストとして妥当な時間よりも長くかかる場合がある。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCが長時間実行でない場合の戻り値の型）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時の完全削除をトリガーできるように、`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態にあるリソース（例：`delete_time`が設定されている）に対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは:expunge接尾辞を持つカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTとしなければならず、body句は"*"としなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`としなければならない。

### 長時間実行のExpunge

Expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに長時間実行オペレーション（AIP-151）に**してもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeするリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）レスポンスに返される**べきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、合理的な期間（30日など）後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、リソースをパージするための合理的な戦略を選択**してもよい**（may）。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験となる：ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むための手書きコードが必要となる。

### エラー

ユーザーがリソースへのアクセス権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラーと**しなければならない**（must）。権限は、リソースの存在確認の前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない場合（作成されていないか、既にexpungeされている）、サービスは`NOT_FOUND`（HTTP 404）でエラーと**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが既に削除されている場合、サービスは`allow_missing`が`true`の場合は成功**しなければならず**（must）、`allow_missing`が`false`の場合は`NOT_FOUND`（HTTP 404）でエラーと**すべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（作成されていないか、既にexpungeされている）をリクエストした場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、readyまたはsoft-deleted状態でない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準のdelete権限とは別に、明示的なexpunge権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
