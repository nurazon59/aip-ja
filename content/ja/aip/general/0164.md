# ソフトデリート

クライアントがソフトデリートと復元（undelete）機能を望む理由はいくつかあるが、
際立った理由が一つある。それはミスからの回復である。
復元をサポートするサービスは、ユーザーが誤って削除したリソースを
回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し復元する必要がある状況に対応するため、
「復元」（undelete）機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドはリソースを
削除済みとしてマークするのみとし、システムから完全に削除しないもの
**でなければならない**（must）。このように動作する場合、
`google.protobuf.Empty`の代わりに更新されたリソースを
返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている
`delete_time`フィールドと`purge_time`フィールドの両方を
持つ**べきである**（should）。さらに、リソースに`state`フィールドが
含まれている場合、そのリソースは`DELETED`状態値を含める**べきである**（should）
（AIP-216）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを
提供する**べきである**（should）。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソース自身で**なければならない**（must）。
  `UndeleteBookResponse`は存在しない。
  - レスポンスは、実現不可能でない限り、完全に設定されたリソースを
    含める**べきである**（should）。
  - undelete RPCが[long-running](#long-running-undelete)の場合、
    レスポンスメッセージはリソース自身に解決される
    `google.longrunning.Operation`で**なければならない**（must）。

### 復元リクエストメッセージ

Undeleteメソッドは共通のリクエストメッセージパターンを実装する。

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。これは`name`と
  呼ぶ**べきである**（should）。
  - フィールドは[requiredとしてアノテーションする][aip-203]**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージに他のrequiredフィールドを含め**てはならない**（must not）。
  また、このAIPまたは他のAIPで説明されているものを除き、他のoptionalフィールドを
  含める**べきではない**（should not）。

### 長時間実行復元

一部のリソースでは、復元に通常のAPIリクエストとしては妥当でない時間がかかる。
この場合、APIは代わりにlong-running operation（AIP-151）を
使用する**べきである**（should）。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- `response_type`はリソースに設定**しなければならない**（must）（RPCが
  long-runningでない場合の戻り値の型）。
- `response_type`フィールドと`metadata_type`フィールドの両方を
  指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除を
トリガーできるようにするための`Expunge`カスタムメソッドを
提供**してもよい**（may）。このメソッドは、現在`CREATING`、`READY`、または
`SOFT_DELETED`状態（`delete_time`が設定されているなど）にあるリソースに
対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを使用するカスタムメソッドで**なければならない**（must）。
- HTTP動詞は`POST`で、`body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージは`google.protobuf.Empty`または
  `google.longrunning.Operation`で**なければならない**（must）。

### 長時間実行完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに
`google.longrunning.Operation`（AIP-151）に**してもよい**（may）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

Expungeメソッドは共通のリクエストメッセージパターンを実装する。

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で
  参照**しなければならない**（must）。
- 他のリクエストフィールドは存在す**べきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）の
レスポンスに返さ**れるべきではない**（should not）（ただし
`bool show_deleted`が`true`の場合は除く）。
ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、
`NOT_FOUND`エラーではなくリソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、それらのリソースをパージするための
合理的な戦略を選択**してもよい**（may）。これには、適切な期間（30日など）後の
自動パージ、ユーザーによる有効期限（AIP-214）の設定、またはリソースの
無期限保持が含まれる。どの戦略を選択する場合でも、APIはソフトデリートされた
リソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされた
リソースよりも劣る体験となる。ソフトデリートされたリソースのIDは、
カスタムメソッド（undelete）が呼び出されない限り再利用できないため、
命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために
手書きのコードが必要になる。

### エラー

リソースが存在するかどうかに関わらず、ユーザーがリソースにアクセスする
権限を持っていない場合、サービスは`PERMISSION_DENIED`（HTTP 403）で
エラー**しなければならない**（must）。権限はリソースの存在確認よりも先に
チェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが
存在しない（作成されたことがないか、既に完全削除された）場合、
サービスは`NOT_FOUND`（HTTP 404）でエラー**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、
リクエストされたリソースが既に削除されている場合、`allow_missing`が
`true`であればサービスは成功**しなければならない**（must）。`allow_missing`が
`false`であれば`NOT_FOUND`（HTTP 404）でエラーにする**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、リクエストされた
リソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で
応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しないリソース（作成されたことがないか、
既に完全削除されたリソース）をリクエストした場合、メソッドは
`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready状態でもソフトデリート状態でもない場合、
メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、
標準のdelete権限とは別の明示的なexpunge権限（例：
`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
