# ソフトデリート

クライアントがソフトデリートおよび Undelete 機能を希望する理由はいくつかあるが、最も重要な理由の一つが際立っている: ミスからの回復である。Undelete をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

API は、ユーザーが誤ってリソースを削除し、回復する能力が必要な状況に対応するために、"undelete" 機能をサポート**してもよい**（may）。

リソースが Undelete をサポートする必要がある場合、`Delete` メソッドは、単にリソースを削除済みとしてマーク**しなければならない**（must）。システムから完全に削除してはならない。この方法で動作する場合、メソッドは `google.protobuf.Empty` の代わりに、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されているとおり、`delete_time` フィールドと `purge_time` フィールドの両方を持つ**べきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を含める**べきである**（should）。

### Undelete

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）:

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 動詞は `POST` で**なければならない**（must）。
- `body` 句は `"*"` で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - Undelete RPC が[長時間実行](#long-running-undelete)である場合、レスポンスメッセージは、リソース自体に解決される `google.longrunning.Operation` で**なければならない**（must）。

### Undelete リクエストメッセージ

Undelete メソッドは、共通のリクエストメッセージパターンを実装する:

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。これは `name` と呼ぶ**べきである**（should）。
  - フィールドは [required としてアノテーションされる][aip-203]**べきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントは、リソースパターンを文書化**すべきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならない**（must not）。また、この AIP または別の AIP で説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### 長時間実行 Undelete

一部のリソースは、通常の API リクエストに対して妥当な時間よりも長く Undelete に時間がかかる。この状況では、API は代わりに long-running operation（AIP-151）を使用**すべきである**（should）:

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプは、リソース（RPC が長時間実行でなかった場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type` フィールドと `metadata_type` フィールドの両方を指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例: `delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI は :expunge サフィックスを持つカスタムメソッドを使用する必要がある。
- HTTP 動詞は POST で、body 句は "*" である必要がある。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` である必要がある。

### 長時間実行 Expunge

Expunge プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）:

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expunge リクエストメッセージ

Expunge メソッドは、共通のリクエストメッセージパターンを実装する:

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、Expunge するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` が true でない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートする API は、妥当な期間（30 日など）後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、これらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。どの戦略が選択されるかにかかわらず、API は、ソフトデリートされたリソースが完全に削除される時期を文書化**すべきである**（should）。

### 宣言的クライアント向けリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいて、ハードデリートされたリソースよりも劣ったエクスペリエンスを持つ。ソフトデリートされたリソースの ID は、カスタムメソッド（Undelete）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースへのアクセス権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラー**しなければならない**（must）。権限は、リソースの存在確認よりも前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない場合（作成されていないか、すでに Expunge されている）、サービスは `NOT_FOUND`（HTTP 404）でエラー**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースがすでに削除されている場合、`allow_missing` が `true` であれば、サービスは成功**しなければならない**（must）。`allow_missing` が `false` であれば、`NOT_FOUND`（HTTP 404）でエラー**すべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが、存在しないリソース（作成されていないか、すでに Expunge されている）をリクエストした場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready またはソフトデリート状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の Delete 権限とは別の、明示的な Expunge 権限（例: `<service>.<resource>.expunge`）を要求**しなければならない**（must）。
