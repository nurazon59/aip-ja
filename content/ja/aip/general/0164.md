# ソフトデリート

クライアントがソフトデリートと削除取り消し（undelete）の機能を望む理由はいくつかあるが、最も重要な理由の1つが際立っている：ミスからの回復である。削除取り消しをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

API は、ユーザーが誤ってリソースを削除し、回復する機能を必要とする状況に対応するために、「削除取り消し」機能をサポート**してもよい**（may）。

リソースが削除取り消しをサポートする必要がある場合、`Delete` メソッドは、単にリソースを削除済みとしてマークし、システムから完全に削除して**はならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されている `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースに `state` フィールド（AIP-216）が含まれる場合、`DELETED` 状態値を**含めるべきである**（should）。

### 削除取り消し（Undelete）

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - 実行不可能でない限り、レスポンスには完全にデータが投入されたリソースを**含めるべきである**（should）。
  - undelete RPC が [long-running](#long-running-undelete) である場合、レスポンスメッセージはリソース自体に解決される `google.longrunning.Operation` **でなければならない**（must）。

### Undelete リクエストメッセージ

Undelete メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。`name` と命名**すべきである**（should）。
  - フィールドは [required としてアノテーション][aip-203] **すべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別**すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージには、本 AIP または他の AIP で説明されているものを除き、他の必須フィールドを含め**てはならず**（must not）、他のオプショナルフィールドを含め**るべきではない**（should not）。

### Long-running undelete

一部のリソースは、通常の API リクエストとして妥当な時間よりも長く削除取り消しに時間がかかる。この状況では、API は代わりに long-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPC が long-running でない場合の戻り値の型）。
- `response_type` と `metadata_type` フィールドの両方を指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタム メソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態にあるリソースに対して動作できる（例：`delete_time` が設定されている）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI は `:expunge` 接尾辞を持つカスタム メソッドを使用しなければならない。
- HTTP 動詞は POST でなければならず、body 句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### Long-running expunge

expunge プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expunge リクエストメッセージ

Expunge メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expunge 対象のリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` が true でない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND` エラーではなく）。

ソフトデリートを行う API は、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。これには、適切な期間（30日など）後の自動パージ、ユーザーが有効期限（AIP-214）を設定できるようにすること、リソースを無期限に保持することなどが含まれる。どの戦略を選択する場合でも、API はソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントにおいて劣った体験をもたらす：ソフトデリートされたリソースの ID は、カスタム メソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタム メソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限は、リソースが存在するかどうかをチェックする前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがない、または既に expunge されている）場合、サービスは `NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは `allow_missing` が `true` であれば成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）でエラーに**すべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されたことがない、または既に expunge されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが ready 状態または soft-deleted 状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の delete 権限とは別の明示的な expunge 権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
