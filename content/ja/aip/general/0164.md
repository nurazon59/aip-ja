# ソフト削除

クライアントがソフト削除と復元機能を望む理由はいくつかあるが、一つの包括的な理由が際立っている：ミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する能力が必要な状況に対応するために、「復元」機能をサポートし**てもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must）。このように動作する場合、メソッドは `google.protobuf.Empty` ではなく、更新されたリソースを返す**べきである**（should）。

ソフト削除をサポートするリソースには、AIP-148で説明されているように `delete_time` と `purge_time` の両方のフィールドが**あるべきである**（should）。さらに、リソースに `state` フィールド（AIP-216）が含まれる場合、リソースは `DELETED` 状態値を含める**べきである**（should）。

### 復元

ソフト削除をサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` **でなければならない**（must）。
- `body` 句は `"*"` **でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - 復元RPCが[長時間実行](#long-running-undelete)の場合、レスポンスメッセージは、リソース自体に解決される `google.longrunning.Operation` **でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを**含めなければならない**（must）。これは `name` と呼ぶ**べきである**（should）。
  - フィールドは[requiredとしてアノテーションする][aip-203]**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならず**（must not）、このAIPまたは別のAIPで説明されているものを除き、他のオプションフィールドを含める**べきではない**（should not）。

### 長時間実行の復元

一部のリソースは、通常のAPIリクエストに合理的な時間よりも長い時間を復元に要する。この状況では、APIは代わりにlong-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCが長時間実行でなかった場合の戻り値の型）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### 完全削除

ソフト削除をサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタムメソッドを提供し**てもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIには `:expunge` 接尾辞を付けたカスタムメソッドを使用しなければならない。
- HTTP動詞はPOSTでなければならず、body句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）にし**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在す**べきではない**（should not）。

### List と Get

ソフト削除されたリソースは、デフォルトでは（`bool show_deleted` がtrueでない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフト削除されたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す**べきである**（should）。

リソースをソフト削除するAPIは、それらのリソースを削除するための合理的な戦略を選択し**てもよい**（may）。これには、合理的な期間（30日など）後の自動削除、ユーザーによる有効期限（AIP-214）の設定許可、またはリソースの無期限保持が含まれる。選択された戦略に関わらず、APIはソフト削除されたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフト削除可能なリソースは、宣言的クライアントにおいてハード削除されたリソースよりも劣るエクスペリエンスを持つ：ソフト削除されたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、そのリソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラー**にしなければならない**（must）。権限は、リソースが存在するかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されていないか、既に完全削除されている）場合、サービスは `NOT_FOUND`（HTTP 404）でエラー**にしなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは `allow_missing` が `true` であれば成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）でエラー**にすべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（作成されていないか、既に完全削除されている）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、readyまたはソフト削除状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
