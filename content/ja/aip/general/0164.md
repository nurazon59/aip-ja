# ソフトデリート

クライアントがソフトデリートとアンデリート機能を望む理由はいくつかあるが、最も重要な理由の一つは、ミスからの回復である。アンデリートをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する能力が必要な状況に対応するために、「アンデリート」機能をサポート**してもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークするだけで、システムから完全には削除しないものと**しなければならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time` と `purge_time` フィールドの両方を持つ**べきである**（should）。さらに、リソースに `state` フィールドが含まれている場合、リソースは `DELETED` 状態値を含める**べきである**（should）（AIP-216）。

### アンデリート

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は `POST` で**なければならない**（must）。
- `body` 句は `"*"` で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスは、実行不可能な場合を除き、完全に設定されたリソースを含める**べきである**（should）。
  - アンデリート RPC が [long-running](#long-running-undelete) である場合、レスポンスメッセージは `google.longrunning.Operation` で**なければならない**（must）。これはリソース自体に解決される。

### アンデリートリクエストメッセージ

アンデリートメソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。これは `name` と呼ばれる**べきである**（should）。
  - フィールドは [requiredとしてアノテーション][aip-203] される**べきである**（should）。
  - フィールドは、参照する [リソースタイプ][aip-123] を識別する**べきである**（should）。
  - フィールドのコメントは、リソースパターンを文書化する**べきである**（should）。
- リクエストメッセージに他の必須フィールドを含め**てはならない**（must not）。また、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### Long-running アンデリート

一部のリソースは、通常のAPIリクエストとしては妥当でないほど、アンデリートに時間がかかる。この状況では、APIは代わりに long-running operation（AIP-151）を使用する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCがlong-runningでない場合の戻り値の型）。
- `response_type` と `metadata_type` フィールドの両方を指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは `:expunge` サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP動詞は `POST` で、`body` 句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### Long-running 完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは、共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、完全削除するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted` が true でない限り）`List`（AIP-132）レスポンスで返される**べきではない**（should not）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、（`NOT_FOUND` エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、妥当な期間（30日など）後の自動完全削除、ユーザーによる有効期限の設定（AIP-214）、リソースの無期限保持など、リソースを完全削除するための合理的な戦略を選択**してもよい**（may）。どの戦略を選択するかにかかわらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣る体験となる。ソフトデリートされたリソースのIDは、（アンデリートという）カスタムメソッドが呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、そのリソースが存在するかどうかにかかわらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限は、リソースが存在するかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない場合（作成されたことがないか、すでに完全削除されている）、サービスは `NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースがすでに削除されている場合、`allow_missing` が `true` であればサービスは成功**しなければならない**（must）。また、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）でエラーにする**べきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソースをリクエストした場合（作成されたことがないか、すでに完全削除されている）、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが ready またはソフトデリート状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
