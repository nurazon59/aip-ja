# ソフトデリート

クライアントがソフトデリートと復元機能を望む理由はいくつかあるが、最も重要な理由はミスからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドはリソースを削除済みとしてマークするだけで、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されている`delete_time`と`purge_time`の両方のフィールドを持つ**べきである**（should）。さらに、リソースが`state`フィールド（AIP-216）を含む場合、リソースは`DELETED`状態値を含める**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - 実行不可能でない限り、レスポンスには完全に設定されたリソースを含める**べきである**（should）。
  - 復元RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージはリソース自体に解決される`google.longrunning.Operation`**でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。`name`と呼ぶ**べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]**すべきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージには、他のrequiredフィールドを含め**てはならず**（must not）、本AIPまたは別のAIPで説明されているものを除き、他のoptionalフィールドを含める**べきではない**（should not）。

### long-running復元

一部のリソースは、通常のAPIリクエストに適した時間よりも長く復元に時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCがlong-runningでない場合の戻り値の型）に設定**しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、`Expunge`カスタム メソッドを提供**してもよい**（may）。これにより、ユーザーはリソースの即時完全削除をトリガーできる。このメソッドは、現在`CREATING`、`READY`、または`SOFT_DELETED`状態にあるリソースに対して動作できる（例：`delete_time`が設定されている）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを持つカスタム メソッドを使用**しなければならない**（must）。
- HTTP動詞は`POST`、`body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`**でなければならない**（must）。

### long-running expunge

expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）**であってもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeするリソースを名前で参照**しなければならない**（must）。
- その他のリクエストフィールドは**存在すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）レスポンスに返される**べきではない**（should not）（`bool show_deleted`がtrueの場合を除く）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND`エラーではなく）。

ソフトデリートを行うAPIは、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。これには、妥当な期間（30日など）後の自動パージ、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持が含まれる。選択された戦略に関係なく、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的クライアント向けリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣った体験となる：ソフトデリートされたリソースのIDは、カスタム メソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタム メソッドの使用を組み込むための手書きコードが必要となる。

### エラー

ユーザーがリソースにアクセスする権限を持たない場合、リソースの存在有無に関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）でエラー**しなければならない**（must）。権限はリソースの存在確認より前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っていても、要求されたリソースが存在しない場合（一度も作成されていないか、既にexpungeされている）、サービスは`NOT_FOUND`（HTTP 404）でエラー**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが既に削除されている場合、サービスは`allow_missing`が`true`であれば成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラー**すべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（一度も作成されていないか、既にexpungeされている）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、readyまたはsoft-deleted状態でない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
