# ソフトデリート

クライアントがソフトデリートとアンデリートの機能を望む理由はいくつかあるが、最も重要な理由は「誤りからの回復」である。アンデリートをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「アンデリート」機能をサポート**してもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete`メソッドは、リソースをシステムから完全に削除するのではなく、削除済みとしてマークするだけと**しなければならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty`の代わりに更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`フィールドと`purge_time`フィールドの両方を持つ**べきである**（should）。さらに、リソースが`state`フィールドを含む場合（AIP-216）、リソースは`DELETED`状態値を含める**べきである**（should）。

### アンデリート

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供する**べきである**（should）。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTPメソッドは`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスには、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - アンデリートRPCが[長時間実行](#long-running-undelete)される場合、レスポンスメッセージはリソース自体に解決される`google.longrunning.Operation`で**なければならない**（must）。

### Undeleteリクエストメッセージ

Undeleteメソッドは、共通のリクエストメッセージパターンを実装する。

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。これは`name`と呼ぶ**べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]する**べきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントはリソースパターンを文書化する**べきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならない**（must not）。また、このAIPまたは他のAIPで説明されているものを除き、他のオプションフィールドを含める**べきではない**（should not）。

### 長時間実行アンデリート

一部のリソースのアンデリートには、通常のAPIリクエストに適した時間よりも長い時間がかかる場合がある。この状況では、APIは代わりにlong-running operation（AIP-151）を使用する**べきである**（should）。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソース（RPCが長時間実行でない場合の戻り型）に設定**しなければならない**（must）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時完全削除をトリガできるように、`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態にあるリソース（例: `delete_time`が設定されている）に対して動作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは`:expunge`サフィックスを使用するカスタムメソッドを使用しなければならない。
- HTTPメソッドはPOSTでなければならず、`body`句は`"*"`でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### 長時間実行Expunge

Expungeプロセスに多大な時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）と**してもよい**（may）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは、共通のリクエストメッセージパターンを実装する。

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、Expunge対象のリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在する**べきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）レスポンスで返す**べきではない**（should not）（ただし`bool show_deleted`がtrueの場合は除く）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、リソースを返す**べきである**（should）（`NOT_FOUND`エラーではなく）。

リソースをソフトデリートするAPIは、妥当な期間（30日など）後の自動完全削除、ユーザーによる有効期限の設定（AIP-214）、またはリソースの無期限保持など、適切な完全削除戦略を選択**してもよい**（may）。どの戦略を選択する場合でも、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化する**べきである**（should）。

### 宣言的クライアント向けリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいて、ハードデリートされたリソースよりも劣る体験をもたらす。ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令的クライアントを導入するか、カスタムメソッドの使用を組み込むための手書きコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースの存在の有無に関わらず、サービスは`PERMISSION_DENIED`（HTTP 403）エラーを返さ**なければならない**（must）。権限はリソースの存在確認よりも先にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがないか、すでにExpungeされている）場合、サービスは`NOT_FOUND`（HTTP 404）エラーを返さ**なければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、`allow_missing`が`true`であればサービスは成功**しなければならない**（must）。`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）エラーを返す**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）を返さ**なければならない**（must）。

`Expunge`を呼び出すユーザーが、存在しないリソース（作成されたことがないか、すでにExpungeされている）を要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースは存在するが、ready状態またはソフトデリート状態にない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準のdelete権限とは別の明示的なExpunge権限（例: `<service>.<resource>.expunge`）を要求**しなければならない**（must）。
