# ソフトデリート

クライアントがソフトデリートと復元機能を必要とする理由はいくつかあるが、最も重要な理由は「ミスからの回復」である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete`メソッドは単にリソースを削除済みとしてマークし、システムから完全に削除し**てはならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty`ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148で説明されているように、`delete_time`フィールドと`purge_time`フィールドの両方を**持つべきである**（should）。さらに、リソースに`state`フィールド（AIP-216）が含まれている場合、リソースは`DELETED`状態値を含む**べきである**（should）。

### 復元

ソフトデリートをサポートするリソースは、`Undelete`メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP動詞は`POST`**でなければならない**（must）。
- `body`句は`"*"`**でなければならない**（must）。
- レスポンスメッセージはリソース自体**でなければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、実現不可能でない限り、完全に設定されたリソースを**含むべきである**（should）。
  - 復元RPCが[長時間実行](#long-running-undelete)の場合、レスポンスメッセージはリソース自体に解決される`google.longrunning.Operation`**でなければならない**（must）。

### 復元リクエストメッセージ

復元メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを**含めなければならない**（must）。これは`name`と呼ば**れるべきである**（should）。
  - フィールドは[requiredとしてアノテーションされる][aip-203]**べきである**（should）。
  - フィールドは参照する[リソースタイプ][aip-123]を**識別すべきである**（should）。
  - フィールドのコメントはリソースパターンを**文書化すべきである**（should）。
- リクエストメッセージは他の必須フィールドを含ん**ではならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを**含むべきではない**（should not）。

### 長時間実行の復元

一部のリソースは、通常のAPIリクエストに対して合理的な時間よりも長く復元にかかる。この状況では、APIは代わりに長時間実行オペレーション（AIP-151）を**使用すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCが長時間実行でなかった場合の戻り値の型）。
- `response_type`フィールドと`metadata_type`フィールドの両方を指定**しなければならない**（must）。

### 完全削除

ソフトデリートをサポートするリソースは、ユーザーが準備完了またはソフトデリート済みのリソースの即時永続的削除をトリガーできるようにする`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在準備完了またはソフトデリート状態（例：`delete_time`が設定されている）のリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは:expungeサフィックスを持つカスタムメソッドを使用**しなければならない**（must）。
- HTTP動詞はPOST**でなければならず**（must）、body句は"*"**でなければならない**（must）。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`**でなければならない**（must）。

### 長時間実行の完全削除

完全削除プロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）に**してもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### 完全削除リクエストメッセージ

完全削除メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは完全削除するリソースを名前で**参照しなければならない**（must）。
- 他のリクエストフィールドは**存在すべきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは（`bool show_deleted`がtrueでない限り）`List`（AIP-132）レスポンスで**返されるべきではない**（should not）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを**返すべきである**（should）。

リソースをソフトデリートするAPIは、合理的な期間（30日など）後の自動パージ、ユーザーが有効期限を設定できるようにする（AIP-214）、またはリソースを無期限に保持することを含む、それらのリソースをパージするための合理的な戦略を**選択してもよい**（may）。どの戦略を選択するかに関わらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを**文書化すべきである**（should）。

### 宣言的クライアントフレンドリーなリソース

ソフトデリート可能なリソースは、ハードデリートされたリソースよりも宣言的クライアントでのエクスペリエンスが劣る：ソフトデリートされたリソースのIDは、カスタムメソッド（復元）が呼び出されない限り再利用できないため、カスタムメソッドの使用を組み込むために命令的クライアントを導入するか、手書きのコードが必要になる。

### エラー

リソースが存在するかどうかに関わらず、ユーザーがリソースにアクセスする権限を持っていない場合、サービスは`PERMISSION_DENIED`（HTTP 403）で**エラーにしなければならない**（must）。権限はリソースが存在するかを確認する前に**チェックしなければならない**（must）。

ユーザーが適切な権限を持っているが、リクエストされたリソースが存在しない（作成されたことがないか、既に完全削除されている）場合、サービスは`NOT_FOUND`（HTTP 404）で**エラーにしなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが既に削除されている場合、`allow_missing`が`true`であればサービスは**成功しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）で**エラーにすべきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、リクエストされたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で**応答しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しない（作成されたことがないか、既に完全削除されている）リソースをリクエストした場合、メソッドは`NOT_FOUND`（HTTP 404）を**返さなければならない**（must）。

リソースが存在するが、準備完了またはソフトデリート状態でない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を**返さなければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な完全削除権限（例：`<service>.<resource>.expunge`）を**要求しなければならない**（must）。
