# ソフトデリート

クライアントがソフトデリートとアンデリート機能を望む理由はいくつかあるが、一つだけ際立つ理由がある。それはミスからの回復である。アンデリートをサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

APIは、ユーザーが誤ってリソースを削除し、回復する必要がある状況に対応するために、「アンデリート」機能をサポート**してもよい**（may）。

リソースがアンデリートをサポートする必要がある場合、`Delete` メソッドは、リソースをシステムから完全に削除するのではなく、単に削除済みとしてマーク**しなければならない**（must）。メソッドがこのように動作する場合、`google.protobuf.Empty` ではなく、更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されているように、`delete_time` と `purge_time` の両方のフィールドを持つ**べきである**（should）。さらに、リソースが `state` フィールドを含む場合（AIP-216）、リソースは `DELETED` 状態値を含める**べきである**（should）。

### Undelete

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供す**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP verbは`POST`で**なければならない**（must）。
- `body`句は`"*"`で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse`は存在しない。
  - レスポンスは、実行不可能でない限り、完全に設定されたリソースを含める**べきである**（should）。
  - undelete RPCが[long-running](#long-running-undelete)である場合、レスポンスメッセージは`google.longrunning.Operation`で**なければならず**（must）、これはリソース自体に解決される。

### Undeleteリクエストメッセージ

Undeleteメソッドは、一般的なリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name`フィールドを含め**なければならない**（must）。これは`name`と呼ばれる**べきである**（should）。
  - フィールドは[requiredとしてアノテーション][aip-203]される**べきである**（should）。
  - フィールドは、参照する[リソースタイプ][aip-123]を識別する**べきである**（should）。
  - フィールドのコメントは、リソースパターンを文書化す**べきである**（should）。
- リクエストメッセージには、他の必須フィールドを含め**てはならず**（must not）、このAIPまたは他のAIPで説明されているものを除き、他のオプショナルフィールドを含める**べきではない**（should not）。

### long-running undelete

一部のリソースは、通常のAPIリクエストでは妥当でないほどundeleteに時間がかかる。この状況では、APIは代わりにlong-running operation（AIP-151）を使用す**べきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCがlong-runningでない場合の戻り値の型）。
- `response_type`と`metadata_type`の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがreadyまたはソフトデリートされたリソースの即時完全削除をトリガーできるようにするために、`Expunge`カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在readyまたはソフトデリート状態にあるリソース（たとえば`delete_time`が設定されている）に対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URIは:expungeサフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP verbはPOSTでなければならず、body句は`"*"`でなければならない。
- レスポンスメッセージは`google.protobuf.Empty`または`google.longrunning.Operation`でなければならない。

### long-running expunge

expungeプロセスにかなりの時間がかかる場合、メソッドは代わりに`google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expungeリクエストメッセージ

Expungeメソッドは、一般的なリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expungeされるリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドを含める**べきではない**（should not）。

### ListとGet

ソフトデリートされたリソースは、デフォルトでは`List`（AIP-132）レスポンスで返される**べきではない**（should not）（`bool show_deleted`がtrueの場合を除く）。ソフトデリートされたリソースに対する`Get`（AIP-131）リクエストは、（`NOT_FOUND`エラーではなく）リソースを返す**べきである**（should）。

リソースをソフトデリートするAPIは、適切な期間（30日など）後の自動purge、ユーザーによる有効期限の設定（AIP-214）、リソースの無期限保持など、それらのリソースをpurgeするための合理的な戦略を選択**してもよい**（may）。どの戦略を選択するかに関わらず、APIはソフトデリートされたリソースがいつ完全に削除されるかを文書化す**べきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいて、ハードデリートされたリソースよりも劣った体験となる。ソフトデリートされたリソースのIDは、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要となる。

### エラー

リソースが存在するかどうかに関わらず、ユーザーがリソースにアクセスする権限を持っていない場合、サービスは`PERMISSION_DENIED`（HTTP 403）でエラーと**しなければならない**（must）。権限は、リソースが存在するかを確認する前にチェック**しなければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない（作成されたことがない、またはすでにexpungeされている）場合、サービスは`NOT_FOUND`（HTTP 404）でエラーと**しなければならない**（must）。

ソフト`Delete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、サービスは`allow_missing`が`true`であれば成功**しなければならず**（must）、`allow_missing`が`false`であれば`NOT_FOUND`（HTTP 404）でエラーとす**べきである**（should）。

`Undelete`を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは`ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge`を呼び出すユーザーが存在しない（作成されたことがない、またはすでにexpungeされている）リソースを要求した場合、メソッドは`NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するがready状態でもソフトデリート状態でもない場合、メソッドは`FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準的な権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準的な削除権限とは別の明示的なexpunge権限（例：`<service>.<resource>.expunge`）を要求**しなければならない**（must）。
