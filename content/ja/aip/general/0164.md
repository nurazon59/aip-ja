# ソフトデリート

クライアントがソフトデリートと復元機能を必要とする理由はいくつかあるが、最も重要な理由は誤りからの回復である。復元をサポートするサービスは、ユーザーが誤って削除したリソースを回復することを可能にする。

## ガイダンス

API は、ユーザーが誤ってリソースを削除し回復する必要がある状況に対応するために、「復元」機能をサポート**してもよい**（may）。

リソースが復元をサポートする必要がある場合、`Delete` メソッドは単にリソースを削除済みとしてマークし、システムから完全に削除**してはならない**（must not）。メソッドがこのように動作する場合、`google.protobuf.Empty` の代わりに更新されたリソースを返す**べきである**（should）。

ソフトデリートをサポートするリソースは、AIP-148 で説明されているように `delete_time` と `purge_time` の両方のフィールドを**持つべきである**（should）。さらに、リソースが `state` フィールドを含む場合、リソースは `DELETED` の状態値を持た**なければならない**（must）（AIP-216）。

### Undelete

ソフトデリートをサポートするリソースは、`Undelete` メソッドを提供**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 動詞は `POST` で**なければならない**（must）。
- `body` 句は `"*"` で**なければならない**（must）。
- レスポンスメッセージはリソース自体で**なければならない**（must）。`UndeleteBookResponse` は存在しない。
  - レスポンスには、実行不可能な場合を除き、完全に設定されたリソースを含める**べきである**（should）。
  - undelete RPC が [long-running](#long-running-undelete) の場合、レスポンスメッセージは `google.longrunning.Operation` で**なければならず**（must）、リソース自体に解決される。

### Undelete リクエストメッセージ

Undelete メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- `name` フィールドを含め**なければならない**（must）。これは `name` と命名**すべきである**（should）。
  - フィールドは [必須としてアノテーション][aip-203]**されるべきである**（should）。
  - フィールドは参照する [リソースタイプ][aip-123] を識別**すべきである**（should）。
  - フィールドのコメントはリソースパターンを文書化**すべきである**（should）。
- リクエストメッセージは他の必須フィールドを含め**てはならず**（must not）、本AIPまたは他のAIPに記載されているものを除き、他の任意フィールドを含める**べきではない**（should not）。

### Long-running undelete

一部のリソースは、通常の API リクエストに許容される時間よりも長い時間をかけて復元される。この状況では、API は代わりに long-running operation（AIP-151）を使用**すべきである**（should）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- レスポンスタイプはリソースに設定**しなければならない**（must）（RPCがlong-runningでない場合の戻り値の型）。
- `response_type` と `metadata_type` の両方のフィールドを指定**しなければならない**（must）。

### Expunge

ソフトデリートをサポートするリソースは、ユーザーがリソースの即時永続削除をトリガーできるようにする `Expunge` カスタムメソッドを提供**してもよい**（may）。このメソッドは、現在 `CREATING`、`READY`、または `SOFT_DELETED` 状態（例：`delete_time` が設定されている）にあるリソースに対して操作できる。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI は `:expunge` サフィックスを持つカスタムメソッドを使用しなければならない。
- HTTP 動詞は POST でなければならず、body 句は `"*"` でなければならない。
- レスポンスメッセージは `google.protobuf.Empty` または `google.longrunning.Operation` でなければならない。

### Long-running expunge

expunge プロセスにかなりの時間がかかる場合、メソッドは代わりに `google.longrunning.Operation`（AIP-151）であっ**てもよい**（may）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expunge リクエストメッセージ

Expunge メソッドは共通のリクエストメッセージパターンを実装する：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- リクエストメッセージは、expunge するリソースを名前で参照**しなければならない**（must）。
- 他のリクエストフィールドは存在**すべきではない**（should not）。

### List と Get

ソフトデリートされたリソースは、デフォルトでは `List`（AIP-132）レスポンスで返さ**れるべきではない**（should not）（`bool show_deleted` が true の場合を除く）。ソフトデリートされたリソースに対する `Get`（AIP-131）リクエストは、`NOT_FOUND` エラーではなくリソースを返す**べきである**（should）。

リソースをソフトデリートする API は、それらのリソースをパージするための合理的な戦略を選択**してもよい**（may）。これには、合理的な期間（30日など）後の自動パージ、ユーザーが有効期限を設定できるようにする（AIP-214）、リソースを無期限に保持することなどが含まれる。どの戦略を選択するかに関わらず、API はソフトデリートされたリソースがいつ完全に削除されるかを文書化**すべきである**（should）。

### 宣言的フレンドリーなリソース

ソフトデリート可能なリソースは、宣言的クライアントにおいてハードデリートされたリソースよりも劣った体験を提供する。ソフトデリートされたリソースの ID は、カスタムメソッド（undelete）が呼び出されない限り再利用できないため、命令型クライアントを導入するか、カスタムメソッドの使用を組み込むために手書きのコードが必要になる。

### エラー

ユーザーがリソースにアクセスする権限を持っていない場合、リソースが存在するかどうかに関わらず、サービスは `PERMISSION_DENIED`（HTTP 403）でエラーに**しなければならない**（must）。権限チェックは、リソースの存在確認よりも前に行わ**なければならない**（must）。

ユーザーが適切な権限を持っているが、要求されたリソースが存在しない場合（一度も作成されていないか、すでに expunge された場合）、サービスは `NOT_FOUND`（HTTP 404）でエラーに**しなければならない**（must）。

ソフト `Delete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースがすでに削除されている場合、`allow_missing` が `true` であればサービスは成功**しなければならず**（must）、`allow_missing` が `false` であれば `NOT_FOUND`（HTTP 404）でエラーに**すべきである**（should）。

`Undelete` を呼び出すユーザーが適切な権限を持っているが、要求されたリソースが削除されていない場合、サービスは `ALREADY_EXISTS`（HTTP 409）で応答**しなければならない**（must）。

`Expunge` を呼び出すユーザーが存在しないリソース（一度も作成されていないか、すでに expunge されたもの）を要求した場合、メソッドは `NOT_FOUND`（HTTP 404）を返さ**なければならない**（must）。

リソースが存在するが、ready またはソフトデリート状態でない場合、メソッドは `FAILED_PRECONDITION`（HTTP 400）を返さ**なければならない**（must）。

標準の権限エラー（`PERMISSION_DENIED`）が適用される。サービスは、標準の削除権限とは別の明示的な expunge 権限を要求**しなければならない**（must）（例：`<service>.<resource>.expunge`）。
