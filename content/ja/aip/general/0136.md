# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に沿うための手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能に対してのみ使用**すべきである**（should）。一貫したセマンティクスを持つため、可能であれば標準メソッドを優先する。（もちろん、これは対象の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドが「なんとか動作する」ように無理に捻じ曲げるのは良い考えでは _ない_。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、サービスのいずれにも関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞に続けて名詞を置いたものに**すべきである**（should）。
  - 名前には前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞には、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含める**べきではない**（should not）。
  - 名前には `Async` という語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する意図がある場合は、接尾辞 `LongRunning` をこの目的で使用**してもよい**（may）。たとえば、long-runningな書籍作成RPCを作成する場合（標準の `CreateBook` メソッドがlong-runningの側面を考慮する前に設計されていた場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` で**なければならない**（must）：
  - `GET` はデータやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要な場合、データ取得メソッドに `POST` を使用**してもよい**（may）。
  - `POST` はメソッドに副作用がある場合やリソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URI は `:` 文字に続けてカスタム動詞（上記の例では `:archive`）を使用**しなければならず**（must）、URI 内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` と**すべきである**（should）。
  - 詳細については、[HTTP と gRPC トランスコーディング][transcoding]を参照。
- カスタムメソッドは、RPC名に `Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。

### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` という名前に**しなければならず**（must）、URIパス内の唯一の変数でなければならない。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、一部のカスタムメソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` という名前に**しなければならず**（must）、URIパス内の唯一の変数でなければならない。
- コレクションキー（上記の例では `books`）はリテラルで**なければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に _ステートレス_ である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を及ぼさない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようにプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URI は、動詞と名詞の両方を `:` 区切りの後に配置**すべきである**（この場合、コレクションがないため、URI に「疑似コレクションキー」を置くのは避ける）。たとえば、`:translateText` は `text:translate` よりも好ましい。
- ステートレスメソッドは、課金を伴う場合は `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらをどう処理すべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作のような、ほとんど使用されず基本的に命令型の操作であり、宣言的サポートが期待されないものである。

## 根拠

### HTTP パス

標準メソッドと同様に、リソースやコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTP メソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）では第一級の概念であり、実行時の影響のリスクなしにどのメソッドを呼び出せるかをユーザーに明確に示す。

`GET` を使用して行われるはずのリクエストに `POST` を使用できることは、便宜のためである：

- URLサイズ制限に違反するリクエストにつながる大きなクエリ文字列を回避できる。
- クライアントがリクエストデータをシリアル化する単一の方法を実装できる。または、少なくともrepeatedフィールドなどの複雑なルールを実装する必要を回避できる。
- 通常は単純なRPCでも、クエリパラメータで表現できないデータを含む複雑な状況に対応できる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、メソッドが別の動詞を使用すべきであることを示している。たとえば、`CreateBook` メッセージがすでに存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor` ではなく、検索次元として `author` フィールドを持つ `SearchBooks` を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC 名

「async」という用語は、RPCの呼び出しを含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用されている。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名内で「async」を使用すると混乱を招き、一部の言語でRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
