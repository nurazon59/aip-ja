# カスタムメソッド

リソース指向設計（AIP-121）では、カスタムメソッドを使用して、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段を提供する。カスタムメソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため、重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドが「なんとなく動作する」ように無理にこじつけるのは良い考えでは*ない*。）

カスタムメソッドの設計は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッドの名前は、動詞の後に名詞を続けたものと**すべきである**（should）。
  - 名前に前置詞（「for」「with」など）を含めて**はならない**（must not）。
  - 名前の動詞に標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**てはならない**（should not）。
  - 名前に `Async` という用語を含めて**はならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する場合は、`LongRunning` サフィックスをこの目的で使用**してもよい**（may）。例えば、長時間実行を作成する書籍作成RPCを作成する場合（標準の `CreateBook` メソッドが長時間実行の側面が検討される前に設計された場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - `GET` は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST` は、リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要となるデータ取得メソッドに使用**してもよい**（may）。
  - `POST` は、メソッドに副作用がある場合、またはリソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URI は `:` 文字の後にカスタム動詞（上記の例では `:archive`）を続け**なければならず**（must）、URI内の動詞はRPCの名前の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` と**すべきである**（should）。
  - 詳細については [HTTP and gRPC Transcoding][transcoding] を参照。
- カスタムメソッドは、RPC名に `Request` サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIがリソースとしてモデル化できる場合、カスタムメソッドはリソースに対して操作を行わ**なければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソースの名前のパラメータは `name` と呼ば**なければならず**（must）、URIパス内の唯一の変数でなければならない。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドはコレクションに対して操作を行っ**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ば**なければならず**（must）、URIパス内の唯一の変数でなければならない。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく紐付かない。これらのメソッドは通常*ステートレス*である：リクエストを受け取ってレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようにプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URI は `:` 区切り文字の後に動詞と名詞の両方を配置**すべきである**（should）（この場合、コレクションがないため、URIに「疑似コレクションキー」を含めない）。例えば、`:translateText` は `text:translate` よりも好ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは、通常カスタムメソッドを採用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらをどう扱うべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作など、宣言的サポートが期待されない、稀にしか使用されない根本的に命令的な操作である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示す `name` または `parent` パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、ランタイムに影響を与えるリスクなしに呼び出せるメソッドをユーザーに明確に示す。

`GET` を使用するべきリクエストに `POST` の使用を許可することは便宜上の措置である：

- 大きなクエリ文字列がURLサイズ制限に違反するリクエストを回避できる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できる、または少なくとも繰り返しフィールドなどに対して複雑なルールを実装する必要がなくなる。
- 通常は単純なRPCであっても、クエリパラメータでは表現できないデータを含む複雑な状況に対応できる。

### 前置詞の禁止

一般的に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、メソッドが別の動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索ディメンションとして `author` フィールドを持つ `SearchBooks` を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

「async」という用語は、プログラミング言語において、RPCの呼び出しを含め、特定のメソッド呼び出しが同期的か非同期的かを示すために一般的に使用される。この同期的/非同期的な側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語でRPCを呼び出すために同期的メソッドと非同期的メソッドの両方を生成するクライアントライブラリでも問題を引き起こす可能性がある。
