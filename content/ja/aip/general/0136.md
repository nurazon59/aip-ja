# カスタム メソッド

リソース指向設計（AIP-121）は、標準メソッドのみではモデル化が難しい任意のアクションを表現する手段として、カスタム メソッドを使用する。カスタム メソッドは、APIの語彙がユーザーの意図に従う手段を提供するため重要である。

## ガイダンス

カスタム メソッドは、標準メソッドでは容易に表現できない機能に対してのみ使用**すべきである**（should）。標準メソッドの一貫したセマンティクスのため、可能であれば標準メソッドを優先する。（もちろん、これは対象の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に当てはめようとするのは*良い考えではない*。）

カスタム メソッドの設計方法は大きく異なるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタム メソッドを示している。カスタム メソッドは、リソース、コレクション、サービスに関連付けることができる。以下の項目は3つのケースすべてに適用される。

- メソッド名は動詞に名詞が続く形**すべきである**（should）。
  - 名前に前置詞（「for」、「with」など）を含めて**はならない**（must not）。
  - 名前の動詞には、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）をいずれも含める**べきではない**（should not）。
  - 名前に`Async`という用語を含めて**はならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別することが意図されている場合、その目的のためにサフィックス`LongRunning`を使用**してもよい**（may）。例えば、標準の`CreateBook`メソッドが長時間実行の側面が考慮される前に設計されており、長時間実行の書籍作成RPCを作成する場合、カスタムの`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - データまたはリソースの状態を取得するメソッドには`GET`を使用**しなければならない**（must）。
  - 副作用がある場合やリソースやデータを変更する場合、メソッドは`POST`を使用**しなければならない**（must）。
- HTTP URIは`:`文字に続けてカスタム動詞を使用**しなければならず**（must）（上記の例では`:archive`）、URI内の動詞はRPCの名前の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`**すべきである**（should）。
  - 詳細については[HTTP and gRPC Transcoding][transcoding]を参照。
- カスタム メソッドはRPC名に`Request`サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタム メソッドはRPC名に`Response`サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して動作する場合、カスタム メソッドはそのリソース自体を返し**てもよい**（may）。


### リソースベースのカスタム メソッド

APIをそのようにモデル化できる場合、カスタム メソッドはリソースに対して動作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼ば**なければならず**（must）、URIパス内の唯一の変数でなければならない。

### コレクションベースのカスタム メソッド

ほとんどのカスタム メソッドは単一のリソースに対して動作するが、一部のカスタム メソッドは代わりにコレクションに対して動作し**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼ば**なければならず**（must）、URIパス内の唯一の変数でなければならない。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタム メソッドはリソースにまったく関連付けられていない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは`:`セパレータの後に動詞と名詞の両方を配置する**べきである**（この場合、「疑似コレクションキー」をURIに含めるのは避ける。コレクションが存在しないため）。例えば、`:translateText`は`text:translate`よりも好ましい。
- ステートレスメソッドは、課金が伴う場合に`POST`を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタム メソッドを使用する**べきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタム メソッドを除く）。なぜなら、宣言的フレンドリーなツールはそれらに対して何をするべきかを自動的に判断できないためである。

この例外は、`Move`や`Rename`操作のような、まれにしか使用されない本質的に命令型の操作であり、宣言的サポートの期待がないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して動作するカスタム メソッドは、動作対象のリソースを示すために`name`または`parent`パラメータを必要とする。この規則により、クライアントはカスタム メソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSourcesなど）で第一級の概念を持ち、どのメソッドがランタイムに影響を与えるリスクなしに呼び出せるかをユーザーに明確に示す。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加するべきところで新しいメソッドが使用されているか、またはメソッドが別個の動詞を使用するべきであることを示す。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIおよびクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの急増を防ぐことができる。

### RPC名

「async」という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用される。この同期/非同期の側面は、RPC自体が長時間実行操作を開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すために同期的メソッドと非同期的メソッドの両方を生成するクライアントライブラリにとって問題を引き起こす可能性さえある。
