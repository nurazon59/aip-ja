# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が困難な任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に沿う手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に歪めることは良い考えでは _ない_。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は、動詞の後に名詞を続けたもの**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前に含まれる動詞は、標準メソッド動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）のいずれかを含ん**ではならない**（must not）。
  - 名前に `Async` という用語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する意図がある場合は、この目的のために接尾辞 `LongRunning` を使用し**てもよい**（may）。例えば、（標準の `CreateBook` メソッドが長時間実行の側面を考慮する前に設計された場合に）長時間実行の書籍作成RPCを作成するには、カスタム `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - `GET` は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要となるデータ取得メソッドには、`POST` を使用し**てもよい**（may）。
  - `POST` は、メソッドに副作用がある場合やリソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、`:` 文字の後にカスタム動詞（上記の例では `:archive`）を続けて使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` **すべきである**（should）。
  - 詳細については [HTTP and gRPC Transcoding][transcoding] を参照。
- カスタムメソッドは、RPC名に一致するリクエストメッセージを受け取り、`Request` 接尾辞を付ける**べきである**（should）。
- カスタムメソッドは、RPC名に一致するレスポンスメッセージを返し、`Response` 接尾辞を付ける**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼ば**なければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、一部のカスタムメソッドは代わりにコレクションに対して操作し**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ば**れなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられていない。これらのメソッドは一般に _ステートレス_ である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URIは、動詞と名詞の両方を `:` 区切り文字の後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URI内の「擬似的なコレクションキー」を避ける）。例えば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは、通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。なぜなら、宣言的フレンドリーなツールはそれらをどう処理すべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作など、ほとんど使用されず根本的に命令的な操作であり、宣言的サポートが期待されない場合である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータが必要である。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、ランタイムへの影響リスクなしに呼び出せるメソッドをユーザーに明確に示す。

### 前置詞の禁止

一般的に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべき箇所で新しいメソッドが使用されているか、またはメソッドが別個の動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索ディメンションとして `author` フィールドを持つ `SearchBooks` を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える、過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

"async" という用語は、RPCの作成を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に "async" を使用すると混乱を招き、一部の言語ではRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
