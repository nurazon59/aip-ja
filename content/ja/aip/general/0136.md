# カスタムメソッド

リソース指向設計（AIP-121）はカスタムメソッドを使用して、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段を提供する。カスタムメソッドは、APIの語彙がユーザーの意図に沿う手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスのために標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに従う場合にのみ適用される。標準メソッドを「なんとか動作させる」ためにものを歪めるのは良い考え方では_ない_。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、サービスのいずれにも関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッドの名前は、動詞の後に名詞が続くものと**すべきである**（should）。
  - 名前には前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞には、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含む**べきではない**（should not）。
  - 名前には `Async` という用語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running
    RPCを区別する意図がある場合、接尾辞 `LongRunning`
    をこの目的で使用**してもよい**（may）。例えば、long-runningな書籍作成RPCを作成する場合（標準の
    `CreateBook` メソッドがlong-runningの側面を考慮する前に設計された場合）、カスタムの
    `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` で**なければならない**（must）：
  - `GET` は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、そのために `body` が必要な場合、`POST`
      をデータ取得メソッドに使用**してもよい**（may）。
  - `POST` は、メソッドに副作用があるか、リソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは `:` 文字の後にカスタム動詞（上記の例では `:archive`）を続けて使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` と**すべきである**（should）。
  - 詳細については [HTTP and gRPC Transcoding][transcoding] を参照。
- カスタムメソッドは、RPC名に一致し `Request` 接尾辞を持つリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に一致し `Response` 接尾辞を持つレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

カスタムメソッドは、APIをそのようにモデル化できる場合、リソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼ば**なければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して操作を行っ**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ばれ、URIパス内の唯一の変数で**なければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラルで**なければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられていない。これらのメソッドは一般に_ステートレス_である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようなプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URIは動詞と名詞の両方を `:` セパレータの後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URI内の「疑似的なコレクションキー」を避けること）。例えば、`:translateText` は `text:translate` よりも好ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで議論されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらに対して何をすべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作など、ほとんど使用されず根本的に命令的な操作であり、宣言的サポートが期待されないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータを必要とする。この規約により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、実行時の影響のリスクなしに呼び出せるメソッドをユーザーに明確に示す。

`GET` を使用して行われるリクエストに対して `POST` を使用できるようにすることは、以下の利便性を提供する：

- URLサイズ制限に違反するリクエストにつながる大きなクエリ文字列を回避できる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにするか、少なくとも繰り返しフィールドなどの複雑なルールを実装する必要を回避する。
- 通常は単純なRPCでも、クエリパラメータで表現できない可能性のあるデータを複雑な状況のために含めることができる。

### 前置詞の禁止

一般的に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドを使用しているか、別の動詞を使用すべきであることを示す。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに `author` フィールドを検索ディメンションとして持つ `SearchBooks` を検討する。これにより、APIサーフェスとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

「async」という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
