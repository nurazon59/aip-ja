# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段としてカスタムメソッドを使用する。カスタムメソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。一貫したセマンティクスを持つ標準メソッドを可能な限り優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに準拠する場合にのみ適用される。標準メソッドが「なんとか動く」ように無理に捻じ曲げるのは良いアイデアでは*ない*。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞の後に名詞が続く形と**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞に標準メソッド動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**るべきではない**（should not）。
  - 名前に`Async`という用語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する意図がある場合、接尾辞`LongRunning`をこの目的で使用**してもよい**（may）。例えば、長時間実行の書籍作成RPCを作成する場合（長時間実行の側面が検討される前に標準の`CreateBook`メソッドが設計されていた場合）、カスタムの`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - `GET`は、データまたはリソース状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST`は、リクエストペイロードがURLサイズ制限を超える可能性があり、そのために`body`が必要な場合、データ取得メソッドに使用**してもよい**（may）。
  - `POST`は、メソッドに副作用がある場合やリソースまたはデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは`:`文字の後にカスタム動詞（上記の例では`:archive`）を使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーション内の`body`句は`"*"`と**すべきである**（should）。
  - 詳細については、[HTTP and gRPC Transcoding][transcoding]を参照。
- カスタムメソッドは、`Request`接尾辞を付けたRPC名と一致するリクエストメッセージを取る**べきである**（should）。
- カスタムメソッドは、`Response`接尾辞を付けたRPC名と一致するレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIがリソースとしてモデル化できる場合、カスタムメソッドはリソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼称**しなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼称**しなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは`:`区切り文字の後に動詞と名詞の両方を配置**すべきである**（should）（この場合、コレクションが存在しないため、URI内の「疑似コレクションキー」を避ける）。例えば、`text:translate`よりも`:translateText`が推奨される。
- ステートレスメソッドは、課金を伴う場合に`POST`を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらをどう扱うべきかを自動的に判断できないためである。

これに対する例外は、`Move`や`Rename`操作など、宣言的サポートの期待がない、まれにしか使用されない本質的に命令型の操作である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示すために`name`または`parent`パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースに対応付けられる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかが明確に区別される。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、実行時の影響リスクなしに呼び出せるメソッドをユーザーに明確に示す。

他の方法では`GET`を使用して行われるリクエストに`POST`の使用を許可することは、便宜のためである：

- URLサイズ制限に違反するような大きなクエリ文字列を回避する。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにする。少なくとも、repeatedフィールドなどの複雑なルールを実装する必要を回避する。
- 通常は単純なRPCでも、クエリパラメータでは表現できない可能性のあるデータを複雑な状況のために含めることができるようにする。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、またはメソッドが別の動詞を使用すべきであることを示す。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIおよびクライアントサーフェスを肥大化させ、APIの管理と消費の両方に複雑さを加える、過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

「async」という用語は、プログラミング言語で特定のメソッド呼び出しが同期的か非同期的かを示すために一般的に使用されており、RPCの実行についても同様である。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語でRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
