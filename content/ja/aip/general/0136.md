# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に沿う手段を提供するため重要である。

## ガイダンス

カスタムメソッド**は**、標準メソッドでは容易に表現できない機能に対してのみ**使用すべきであり**（should）、一貫したセマンティクスを持つ標準メソッドを可能であれば優先する。（もちろん、これは対象の機能が通常のセマンティクスに実際に適合する場合にのみ適用される。標準メソッドを「なんとか動くようにする」ために事物を歪曲することは良い考えでは*ない*。）

カスタムメソッドの設計は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞とそれに続く名詞**であるべきである**（should）。
  - 名前に前置詞（「for」「with」など）を**含めてはならない**（must not）。
  - 名前に含まれる動詞は標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を**含めるべきではない**（should not）。
  - 名前に `Async` という語を**含めてはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する目的であれば、`LongRunning` サフィックスを**使用してもよい**（may）。例えば、長時間実行の書籍作成RPCを作成する場合（標準の `CreateBook` メソッドが長時間実行の側面を考慮する前に設計されていた場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - `GET` はデータまたはリソースの状態を取得するメソッドに**使用しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要な場合、データ取得メソッドに `POST` を**使用してもよい**（may）。
  - `POST` は副作用がある場合、またはリソースやデータを変更する場合に**使用しなければならない**（must）。
- HTTP URI は `:` 文字に続けてカスタム動詞を使用**しなければならず**（must）（上記の例では `:archive`）、URI 内の動詞はRPC名の動詞と**一致しなければならない**（must）。
  - 単語の区切りが必要な場合は `camelCase` を**使用しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` **であるべきである**（should）。
  - 詳細については [HTTP と gRPC トランスコーディング][transcoding] を参照。
- カスタムメソッドはRPC名に `Request` サフィックスを付けたリクエストメッセージを**受け取るべきである**（should）。
- カスタムメソッドはRPC名に `Response` サフィックスを付けたレスポンスメッセージを**返すべきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソース自体を**返してもよい**（may）。

### リソースベースのカスタムメソッド

カスタムメソッドは、APIがそのようにモデル化できる場合はリソースに対して**操作しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と**呼ばなければならず**（must）、URI パス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して**操作してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と**呼ばなければならず**（must）、URI パス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では `books`）は**リテラルでなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドはリソースにまったく紐付かない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API 内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は `snake_case` を**使用しなければならない**（must）。
- URI は `:` 区切りの後に動詞と名詞の両方を**配置すべきである**（should）（この場合、コレクションが存在しないため、URI 内で「疑似コレクションキー」を避ける）。例えば、`text:translate` よりも `:translateText` が望ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を**使用しなければならない**（must）。

### 宣言的クライアント向けリソース

宣言的クライアント向けリソースは通常、カスタムメソッドを**使用すべきではない**（should）（他のAIPで議論される特定の宣言的クライアント向けカスタムメソッドを除く）。宣言的クライアント向けツールはカスタムメソッドをどう処理すべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作のような、ほとんど使用されない基本的に命令型の操作であり、宣言的サポートが期待されないものである。

## 根拠

### HTTP パス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTP メソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（Terraform の DataSources など）で第一級の概念を持ち、ランタイムへの影響なしに呼び出せるメソッドをユーザーに明確に示す。

通常であれば `GET` を使用するリクエストに `POST` を使用できるようにすることは利便性のためである：

- URL サイズ制限に違反する大きなクエリ文字列を回避できる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるか、少なくとも repeated フィールドなどの複雑なルールを実装する必要を回避できる。
- 通常は単純な RPC であっても、クエリパラメータで表現できないデータを含む複雑な状況に対応できる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使われているか、またはメソッドが別の動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索ディメンションとして `author` フィールドを持つ `SearchBooks` を検討する。これは、API とクライアントのサーフェスを肥大化させ、API の管理と利用の両方に複雑さを加える、過剰に特化したメソッドの爆発的な増加を防ぐのに役立つ。

### RPC 名

「async」という用語は、RPC の呼び出しを含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC 自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC 名自体に「async」を使用すると混乱を招き、一部の言語では RPC を呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリでも問題を引き起こす可能性がある。
