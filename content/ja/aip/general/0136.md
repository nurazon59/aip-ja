# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段を提供するために、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に従う手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫した意味論を持つ標準メソッドを優先すること。（もちろん、これは対象の機能が実際に通常の意味論に適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために物事を歪めるのは良い考えでは_ない_。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッドの名前は、動詞の後に名詞を続けたものと**すべきである**（should）。
  - 名前に前置詞（"for"、"with" など）を含め**てはならない**（must not）。
  - 名前に含まれる動詞は、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含める**べきではない**（should not）。
  - 名前には `Async` という用語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する意図がある場合、その目的のためにサフィックス `LongRunning` を使用**してもよい**（may）。例えば、long-runningな書籍作成RPCを作成する場合（標準の `CreateBook` メソッドがlong-runningの側面が考慮される前に設計された場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` で**なければならない**（must）：
  - `GET` は、データやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLのサイズ制限を超える可能性があり、そのために `body` が必要になる場合、`POST` をデータ取得メソッドに使用**してもよい**（may）。
  - メソッドに副作用がある、またはリソースやデータを変更する場合、`POST` を使用**しなければならない**（must）。
- HTTP URIは、カスタム動詞（上記の例では `:archive`）の前に `:` 文字を使用**しなければならない**（must）。また、URI内の動詞はRPCの名前の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` と**すべきである**（should）。
  - 詳細については、[HTTP and gRPC Transcoding][transcoding] を参照すること。
- カスタムメソッドは、RPC名に `Request` サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

カスタムメソッドは、APIがリソースとしてモデル化できる場合、リソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼ばれ、URIパス内の唯一の変数で**なければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、一部のカスタムメソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ばれ、URIパス内の唯一の変数で**なければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラルで**なければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に_ステートレス_である。リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合、`snake_case` を使用**しなければならない**（must）。
- URIは、動詞と名詞の両方を `:` 区切りの後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URIに「偽のコレクションキー」を避けること）。例えば、`text:translate` よりも `:translateText` が望ましい。
- ステートレスメソッドは、課金を伴う場合、`POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは、通常カスタムメソッドを使用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらをどう処理すべきか自動的に判断できないためである。

この例外は、ほとんど使用されない、本質的に命令型の操作（`Move` や `Rename` 操作など）であり、宣言的サポートが期待されないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースやコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータを必要とする。この規約により、クライアントはカスタムメソッドを適切なリソースに対応付けることができる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかが明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、実行時の影響のリスクなしに呼び出せるメソッドをユーザーに明確に示す。

通常 `GET` で行われるリクエストに `POST` を使用できるようにすることは、以下の利便性を提供する：

- 大きなクエリ文字列によるURLサイズ制限違反を回避する。
- クライアントがリクエストデータを単一の方法でシリアライズできるようにし、少なくともrepeatedフィールドなどのための複雑なルールを実装する必要を回避する。
- 通常は単純なRPCでも、クエリパラメータでは表現できない可能性のある複雑な状況のためのデータを含めることができる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、またはメソッドが別の動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討すること。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` ではなく、`author` フィールドを検索ディメンションとして持つ `SearchBooks` を検討すること。これにより、APIやクライアントのサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

"async"という用語は、RPCの呼び出しを含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に"async"を使用すると混乱を招き、一部の言語ではRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
