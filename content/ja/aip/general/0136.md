# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドのみを使用してモデル化するのが難しい任意のアクションを表現する手段としてカスタムメソッドを使用する。カスタムメソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ**使用すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは対象の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に歪めることは*良い*アイデアではない。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きはこれら3つのケースすべてに適用される。

- メソッドの名前は動詞に続いて名詞を付けたもの**にすべきである**（should）。
  - 名前には前置詞（"for"、"with"など）を**含めてはならない**（must not）。
  - 名前に含まれる動詞は、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を**含むべきではない**（should not）。
  - 名前には`Async`という用語を**含めてはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する目的がある場合、接尾辞`LongRunning`をこの目的に**使用してもよい**（may）。例えば、標準の`CreateBook`メソッドが長時間実行の側面を考慮する前に設計されていた場合に、長時間実行の書籍作成RPCを作成するには、カスタムの`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - `GET`は、データまたはリソースの状態を取得するメソッドに**使用しなければならない**（must）。
    - リクエストペイロードがURLサイズの制限を超える可能性があり、`body`が必要となる場合、データ取得メソッドに`POST`を**使用してもよい**（may）。
  - `POST`は、メソッドが副作用を持つか、リソースやデータを変更する場合に**使用しなければならない**（must）。
- HTTP URIでは、`:`文字に続けてカスタム動詞（上記の例では`:archive`）を**使用しなければならず**（must）、URI内の動詞はRPCの名前の動詞と**一致しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`**を使用しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`**にすべきである**（should）。
  - 詳細については[HTTP and gRPC Transcoding][transcoding]を参照。
- カスタムメソッドは、RPC名に`Request`接尾辞を付けたリクエストメッセージを**受け取るべきである**（should）。
- カスタムメソッドは、RPC名に`Response`接尾辞を付けたレスポンスメッセージを**返すべきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソース自体を**返してもよい**（may）。


### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作を**行わなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソースの名前のパラメータは`name`**と呼ばなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して操作を**行ってもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`**と呼ばれなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく紐付かない。これらのメソッドは一般に*ステートレス*であり、リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前**にすべきである**（should）。単語の区切りが必要な場合は、`snake_case`**を使用しなければならない**（must）。
- URIでは、動詞と名詞の両方を`:`区切りの後ろに**置くべきである**（should）（この場合、コレクションが存在しないため、URI内で「疑似コレクションキー」を避ける）。例えば、`:translateText`は`text:translate`よりも望ましい。
- 課金を伴う場合、ステートレスメソッドは`POST`**を使用しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを**使用すべきではない**（should）（他のAIPで説明される特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらをどう扱うべきかを自動的に判断できないためである。

これに対する例外は、`Move`や`Rename`操作など、まれにしか使用されず本質的に命令型である操作についてであり、これらには宣言的サポートの期待がない。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示すために`name`または`parent`パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSourcesなど）で第一級の概念を持ち、実行時の影響のリスクなしに呼び出せるメソッドをユーザーに明確に示す。

他の方法では`GET`を使用するリクエストに`POST`を使用できるようにすることは、便宜上の措置である：

- 大きなクエリ文字列がURLサイズの制限に違反するリクエストを回避する。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにするか、少なくとも繰り返しフィールドなどに対する複雑なルールの実装を回避する。
- 通常は単純なRPCでも、クエリパラメータで表現できないデータを含む複雑な状況に対応できるようにする。

### 前置詞の禁止

一般的に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべき箇所で新しいメソッドが使用されているか、メソッドが別の動詞を使用すべきであることを示している。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える、過度に特化したメソッドの爆発的増加を防ぐことができる。

### RPC名

「async」という用語は、RPCの作成を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリにおいて問題を引き起こすことさえある。
