# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドのみを使用してモデル化するのが困難な任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは簡単に表現できない機能にのみ使用**すべきである**（should）。標準メソッドの一貫したセマンティクスのため、可能であれば標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか機能させる」ために無理に歪めるのは*良くない*考えである。）

カスタムメソッドの設計は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞の後に名詞が続く形に**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞は標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**てはならない**（must not）。
  - 名前に`Async`という用語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別することが目的である場合、この目的のためにサフィックス`LongRunning`を使用**してもよい**（may）。例えば、長時間実行の要素が考慮される前に標準の`CreateBook`メソッドが設計されていた場合、長時間実行の書籍作成RPCを作成するために、カスタムの`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - `GET`はデータやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
  - `POST`は副作用があるメソッドやリソースやデータを変更するメソッドに使用**しなければならない**（must）。
- HTTP URIにはカスタム動詞の前に`:`文字を使用**しなければならず**（must）（上記の例では`:archive`）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語区切りが必要な場合は`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`に**すべきである**（should）。
  - 詳細については[HTTP and gRPC Transcoding][transcoding]を参照。
- カスタムメソッドは、RPC名に`Request`サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に`Response`サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作を**行わなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼ば**なければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して操作を**行ってもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼ば**れなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく結びついていない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語区切りが必要な場合は`snake_case`を使用**しなければならない**（must）。
- URIは`:`セパレータの後に動詞と名詞の両方を配置**すべきである**（この場合、コレクションが存在しないため、URI内の「疑似コレクションキー」を避ける）。例えば、`:translateText`は`text:translate`よりも好ましい。
- ステートレスメソッドが課金を伴う場合、`POST`を使用**しなければならない**（must）。

### 宣言的クライアントフレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを採用**すべきではない**（should not）（他のAIPで議論される特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらに対して何をすべきかを自動的に判断できないためである。

これに対する例外は、`Move`や`Rename`操作など、まれにしか使用されない根本的に命令的な操作であり、宣言的サポートの期待はない。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示すために`name`または`parent`パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、ランタイム影響のリスクなしにどのメソッドを呼び出せるかをユーザーに明確に示す。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、メソッドが別の動詞を使用すべきであることを示している。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが望まれる場合、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に焦点化されたメソッドの爆発を防ぐことができる。

### RPC名

「async」という用語は、プログラミング言語で特定のメソッド呼び出しが同期的か非同期的かを示すために一般的に使用されており、RPCの作成も含まれる。この同期/非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用することは混乱を引き起こし、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリで問題を引き起こす可能性さえある。
