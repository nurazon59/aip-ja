# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段としてカスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に従う手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきであり**（should）、一貫したセマンティクスを持つ標準メソッドを可能な限り優先**すべきである**（should）。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に歪めるのは良い考えでは*ない*。）

カスタムメソッドは設計方法が多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは、すべての3つのケースに適用される。

- メソッド名は動詞＋名詞の形式と**すべきである**（should）。
  - 名前に前置詞（「for」「with」など）を含め**てはならない**（must not）。
  - 名前に含まれる動詞は、標準メソッド動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を一切含ま**ないようにすべきである**（should not）。
  - 名前に`Async`という用語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する意図がある場合、接尾辞`LongRunning`をこの目的で使用**してもよい**（may）。例えば、標準の`CreateBook`メソッドが長時間実行の側面が考慮される前に設計された場合に、長時間実行の書籍作成RPCを作成するために、カスタムメソッド`CreateBookLongRunning`を導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - `GET`は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、そのために`body`が必要となる場合、データ取得メソッドに`POST`を使用**してもよい**（may）。
  - `POST`は、メソッドが副作用を持つか、リソースまたはデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、`:`文字に続いてカスタム動詞（上記の例では`:archive`）を使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`と**すべきである**（should）。
  - 詳細については[HTTPとgRPCのトランスコーディング][transcoding]を参照。
- カスタムメソッドは、RPC名に`Request`接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に`Response`接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。

### リソースベースのカスタムメソッド

カスタムメソッドは、APIがリソースとしてモデル化できる場合、リソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼称**しなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、一部のカスタムメソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼称**しなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドはリソースにまったく関連付けられない。これらのメソッドは一般に*ステートレス*である。リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは、動詞と名詞の両方を`:`区切りの後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URIに「疑似コレクションキー」を置くことは避ける）。例えば、`:translateText`は`text:translate`よりも望ましい。
- ステートレスメソッドは、課金を伴う場合に`POST`を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは、通常カスタムメソッドを使用**すべきではない**（should not）（他のAIPで議論されている特定の宣言的フレンドリーなカスタムメソッドを除く）。なぜなら、宣言的フレンドリーなツールはそれらを自動的にどう処理すればよいか判断できないからである。

これに対する例外は、`Move`や`Rename`操作など、宣言的サポートが期待されない、まれにしか使用されない根本的に命令的な操作の場合である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示すために`name`または`parent`パラメータを必要とする。この規約により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、どのメソッドが実行時の影響リスクなしに呼び出せるかをユーザーに明確に示す。

通常なら`GET`で行われるリクエストに`POST`の使用を許可することは便宜である：

- 大きなクエリ文字列がURLサイズ制限に違反するリクエストを回避できる。
- クライアントがリクエストデータをシリアル化する単一の方法を実装でき、少なくとも繰り返しフィールドなどのための複雑なルールを実装する必要がなくなる。
- 通常は単純なRPCであっても、クエリパラメータで表現できないデータを含む複雑な状況に対応できる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、またはメソッドが別個の動詞を使用すべきであることを示している。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合は、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIとクライアントのサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過剰に焦点を絞ったメソッドの爆発的増加を防ぐことができる。

### RPC名

「async」という用語は、プログラミング言語において、RPCの作成を含む特定のメソッド呼び出しが同期か非同期かを示すために一般的に使用される。この同期/非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を引き起こし、一部の言語でRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリで問題を引き起こすことさえある。
