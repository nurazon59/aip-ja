# カスタム メソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタム メソッドを使用する。カスタム メソッドは、APIの語彙がユーザーの意図に適合する手段を提供するため重要である。

## ガイダンス

カスタム メソッドは、標準メソッドで容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、標準メソッドを優先すること。標準メソッドは一貫したセマンティクスを持つためである。（もちろん、これは問題となる機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために物事を歪めるのは良いアイデアでは*ない*。）

カスタム メソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタム メソッドを示している。カスタム メソッドは、リソース、コレクション、サービスのいずれに関連付けることもできる。以下の箇条書きは、この3つのケースすべてに適用される。

- メソッド名は動詞の後に名詞を続けたものと**すべきである**（should）。
  - メソッド名に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - メソッド名の動詞に標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含める**べきではない**（should not）。
  - メソッド名に`Async`という用語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する意図がある場合は、この目的で`LongRunning`サフィックスを使用**してもよい**（may）。例えば、long-runningを考慮する前に標準の`CreateBook`メソッドが設計された場合に、long-runningな本作成RPCを作成するには、カスタムの`CreateBookLongRunning`メソッドを導入することが考えられる。
- HTTPメソッドは`GET`または`POST`と**しなければならない**（must）：
  - `GET`はデータやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST`は、リクエストペイロードがURLサイズ制限を超える可能性があり、`body`を必要とする場合に、データ取得メソッドに使用**してもよい**（may）。
  - `POST`は、メソッドに副作用がある場合やリソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、`:`文字の後にカスタム動詞（上記の例では`:archive`）を続けた形式を使用**しなければならない**（must）。また、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`と**すべきである**（should）。
  - 詳細については[HTTP and gRPC Transcoding][transcoding]を参照。
- カスタム メソッドは、RPC名に一致し`Request`サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタム メソッドは、RPC名に一致し`Response`サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタム メソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタム メソッド

カスタム メソッドは、APIがそのようにモデル化できる場合、リソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と名付けられ、URIパス内の唯一の変数と**しなければならない**（must）。

### コレクションベースのカスタム メソッド

ほとんどのカスタム メソッドは単一のリソースに対して操作を行うが、一部のカスタム メソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と名付けられ、URIパス内の唯一の変数と**しなければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラルと**しなければならない**（must）。

### ステートレスメソッド

一部のカスタム メソッドは、リソースにまったく結びついていない。これらのメソッドは一般的に*ステートレス*である。つまり、リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは、動詞と名詞の両方を`:`セパレータの後に置く**べきである**（should）（この場合、コレクションが存在しないため、URI内に「疑似コレクションキー」を置くことは避ける）。例えば、`:translateText`は`text:translate`よりも望ましい。
- ステートレスメソッドは、課金を伴う場合に`POST`を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは、通常カスタム メソッドを使用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタム メソッドを除く）。宣言的フレンドリーなツールは、それらをどう処理すればよいかを自動的に判断できないためである。

この例外は、`Move`や`Rename`操作など、まれにしか使用されず本質的に命令型の操作であり、宣言的サポートが期待されない場合である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースやコレクションに対して操作を行うカスタム メソッドには、操作対象のリソースを示す`name`または`parent`パラメータが必要である。この規則により、クライアントはカスタム メソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかが明確に区別される。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）でファーストクラスの概念として扱われ、どのメソッドが実行時の影響のリスクなしに呼び出せるかをユーザーに明確に示す。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、フィールドを既存のメソッドに追加すべき場合や、メソッドが別の動詞を使用すべき場合に、新しいメソッドが使われていることを示す。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合は、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIおよびクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える、過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

「async」という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは、異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
