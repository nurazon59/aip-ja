# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段としてカスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に沿う手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。標準メソッドの方が一貫したセマンティクスを持つため、可能であれば標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動かす」ために無理に歪めるのは良い考えでは*ない*。）

カスタムメソッドの設計は多種多様であるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッドの名前は、動詞の後に名詞が続く形式に**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞に標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**てはならない**（should not）。
  - 名前に `Async` という語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する意図がある場合、`LongRunning` サフィックスをこの目的で使用**してもよい**（may）。例えば、標準の `CreateBook` メソッドがlong-runningの側面が考慮される前に設計された場合に、long-runningの書籍作成RPCを作成するために、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - データまたはリソースの状態を取得するメソッドには `GET` を使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要となる場合、データ取得メソッドに `POST` を使用**してもよい**（may）。
  - メソッドが副作用を持つ、またはリソースやデータを変更する場合は `POST` を使用**しなければならない**（must）。
- HTTP URIは、`:` 文字に続いてカスタム動詞（上記の例では `:archive`）を使用**しなければならず**（must）、URI内の動詞はRPCの名前の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` **にすべきである**（should）。
  - 詳細については [HTTP と gRPC トランスコーディング][transcoding] を参照。
- カスタムメソッドは、RPC名に `Request` サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して動作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して動作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼称**しなければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して動作するが、一部のカスタムメソッドは代わりにコレクションに対して動作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼称**しなければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は `snake_case` を使用**しなければならない**（must）。
- URIは、`:` 区切り文字の後に動詞と名詞の両方を配置**すべきである**（この場合、コレクションが存在しないため、URI内の「擬似コレクションキー」を避ける）。例えば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合 `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを採用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらを自動的にどう処理すべきかを判断できないためである。

これの例外は、`Move` や `Rename` 操作のような、まれにしか使用されず、根本的に命令的な操作であり、宣言的サポートが期待されないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して動作するカスタムメソッドは、操作対象のリソースを示す `name` または `parent` パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSourcesなど）で第一級の概念を持ち、実行時の影響リスクなしにどのメソッドを呼び出せるかをユーザーに明確に示す。

通常 `GET` を使用して行われるリクエストに `POST` を使用できることは便宜である：

- URLサイズ制限に違反するリクエストにつながる大きなクエリ文字列を回避する。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにする、または少なくともrepeatedフィールドなどの複雑なルールを実装する必要を回避する。
- 通常は単純なRPCでも、クエリパラメータで表現できない可能性のあるデータを複雑な状況のために含めることを可能にする。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべき箇所で新しいメソッドが使用されているか、メソッドが別の動詞を使用すべきであることを示す。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合は、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor` の代わりに、検索次元として `author` フィールドを持つ `SearchBooks` を検討する。これは、APIおよびクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過度に特化したメソッドの爆発的増加を防ぐのに役立つ。

### RPC名

「async」という用語は、RPCの作成を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用されている。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語でRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリで問題を引き起こす可能性さえある。
