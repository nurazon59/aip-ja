# カスタム メソッド

リソース指向設計（AIP-121）では、カスタム メソッドを使用して、標準メソッドだけではモデル化が困難な任意のアクションを表現する手段を提供する。カスタム メソッドは、APIの語彙がユーザーの意図に適合するための手段を提供するため重要である。

## ガイダンス

カスタム メソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理にねじ曲げることは良い考えでは*ない*。）

カスタム メソッドの設計方法は大きく異なるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタム メソッドを示している。カスタム メソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の項目は3つのケースすべてに適用される。

- メソッド名は動詞に名詞が続く形に**すべきである**（should）。
  - 名前に前置詞（「for」、「with」など）を含め**てはならない**（must not）。
  - 名前の動詞には標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**てはならない**（should not）。
  - 名前に`Async`という用語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する意図がある場合は、その目的のために`LongRunning`サフィックスを使用**してもよい**（may）。例えば、標準の`CreateBook`メソッドがlong-runningの側面が考慮される前に設計された場合に、long-runningのブック作成RPCを作成するためには、カスタム`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - `GET`は、データまたはリソース状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST`は、リクエストペイロードがURLサイズの制限を超える可能性があり、`body`が必要となる場合に、データ取得メソッドに使用**してもよい**（may）。
  - `POST`は、メソッドに副作用がある場合やリソースまたはデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、カスタム動詞の前に`:`文字を使用**しなければならず**（must）（上記の例では`:archive`）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`に**すべきである**（should）。
  - 詳細については[HTTP and gRPC Transcoding][transcoding]を参照。
- カスタム メソッドは、RPC名に`Request`サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタム メソッドは、RPC名に`Response`サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して動作する場合、カスタム メソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタム メソッド

APIがそのようにモデル化できる場合、カスタム メソッドはリソースに対して動作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼ば**なければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。

### コレクションベースのカスタム メソッド

ほとんどのカスタム メソッドは単一のリソースに対して動作するが、一部のカスタム メソッドは代わりにコレクションに対して動作し**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼ば**れなければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタム メソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようにプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは、動詞と名詞の両方を`:`セパレータの後に配置する**べきである**（should）（この場合、コレクションが存在しないため、URI内の「偽のコレクションキー」を避ける）。例えば、`:translateText`は`text:translate`よりも好ましい。
- ステートレスメソッドは、課金を伴う場合に`POST`を使用**しなければならない**（must）。

### 宣言的クライアント向けリソース

宣言的クライアント向けリソースは通常、カスタム メソッドを採用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的クライアント向けカスタム メソッドを除く）。これは、宣言的クライアント向けツールがそれらをどう処理するかを自動的に判断できないためである。

これに対する例外は、ほとんど使用されない根本的に命令的な操作（`Move`や`Rename`操作など）であり、宣言的サポートの期待がないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して動作するカスタム メソッドは、操作対象のリソースを示す`name`または`parent`パラメータを必要とする。この規則により、クライアントはカスタム メソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、どのメソッドがランタイムへの影響リスクなしに呼び出せるかをユーザーに明確に示す。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、メソッドが別個の動詞を使用すべきであることを示す。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合は、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの爆発的増加を防ぐことができる。

### RPC名

「async」という用語は、RPCの作成を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を引き起こし、一部の言語ではRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリで問題を引き起こす可能性さえある。
