# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能に対してのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先すること（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動く」ように無理に当てはめようとすることは*良い*アイデアではない）。

カスタムメソッドは設計方法が多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッドの名前は、動詞の後に名詞を続けたものと**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞に標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**るべきではない**（should not）。
  - 名前に`Async`という語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する意図がある場合、接尾辞`LongRunning`を使用**してもよい**（may）。例えば、長時間実行の観点が考慮される前に標準の`CreateBook`メソッドが設計されていた場合に、長時間実行の書籍作成RPCを作成するには、カスタムの`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`と**しなければならない**（must）：
  - `GET`は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST`は、リクエストペイロードがURLサイズの制限を超える可能性があり、`body`が必要となる場合、データ取得メソッドに使用**してもよい**（may）。
  - `POST`は、メソッドに副作用があるか、リソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、カスタム動詞の前に`:`文字を使用**しなければならず**（must）（上記の例では`:archive`）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の分離が必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーション内の`body`句は`"*"`と**すべきである**（should）。
  - 詳細については[HTTP and gRPC Transcoding][transcoding]を参照すること。
- カスタムメソッドは、RPC名に`Request`接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に`Response`接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して動作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

カスタムメソッドは、APIがそのようにモデル化できる場合、リソースに対して動作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼ば**なければならず**（must）、URIパス内の唯一の変数と**しなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して動作するが、一部のカスタムメソッドは代わりにコレクションに対して動作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼ば**なければならず**（must）、URIパス内の唯一の変数と**しなければならない**（must）。
- コレクションキー（上記の例では`books`）はリテラルと**しなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは、動詞と名詞の両方を`:`区切りの後に配置する**べきである**（should）（この場合、コレクションが存在しないため、URI内の「疑似コレクションキー」を避けること）。例えば、`text:translate`よりも`:translateText`が望ましい。
- ステートレスメソッドは、課金を伴う場合、`POST`を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは、通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらをどう処理すべきかを自動的に判断できないためである。

これに対する例外は、`Move`や`Rename`操作など、まれにしか使用されず、根本的に命令的な操作であり、宣言的サポートの期待がない場合である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して動作するカスタムメソッドは、動作対象のリソースを示す`name`または`parent`パラメータを必要とする。この規約により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）において第一級の概念として扱われ、どのメソッドがランタイムへの影響のリスクなしに呼び出せるかをユーザーに明確に示す。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、またはメソッドが別個の動詞を使用すべきであることを示す。例えば、`CreateBook`メッセージが既に存在し、`CreateBookFromDictation`の追加を検討している場合、代わりに`TranscribeBook`メソッドを検討すること。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討すること。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過度に特化したメソッドの爆発的増加を防ぐことができる。

### RPC名

"async"という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に"async"を使用すると混乱を招き、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こすことさえある。
