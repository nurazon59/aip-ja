# カスタムメソッド

リソース指向設計（AIP-121）では、カスタムメソッドを使用して、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段を提供する。カスタムメソッドは、APIの語彙がユーザーの意図に従う手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。標準メソッドの一貫したセマンティクスのため、可能であれば標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に捻じ曲げるのは良い考えでは*ない*。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは、これら3つのケースすべてに適用される。

- メソッド名は動詞に続いて名詞を置く形と**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を**含めてはならない**（must not）。
  - 名前の動詞は、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を**含めるべきではない**（should not）。
  - 名前に `Async` という用語を**含めてはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する意図がある場合、この目的で接尾辞 `LongRunning` を**使用してもよい**（may）。例えば、long-runningな書籍作成RPCを作成する場合（標準の `CreateBook` メソッドがlong-runningの側面が考慮される前に設計されていた場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - データまたはリソースの状態を取得するメソッドには `GET` を**使用しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要となる場合、データ取得メソッドに `POST` を**使用してもよい**（may）。
  - メソッドに副作用がある場合、またはリソースやデータを変更する場合は `POST` を**使用しなければならない**（must）。
- HTTP URIは `:` 文字の後にカスタム動詞（上記の例では `:archive`）を続けて**使用しなければならず**（must）、URI内の動詞はRPC名の動詞と**一致しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を**使用しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` と**すべきである**（should）。
  - 詳細については[HTTPとgRPCトランスコーディング][transcoding]を参照。
- カスタムメソッドは、RPC名に `Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソースそのものを返して**もよい**（may）。


### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作を**行わなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と**呼ばなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して操作を**行ってもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と**呼ばなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられていない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようにプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前と**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を**使用しなければならない**（must）。
- URIは `:` 区切り文字の後に動詞と名詞の両方を配置**すべきである**（この場合、コレクションが存在しないため、URIに「擬似コレクションキー」を使用しない）。例えば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合は `POST` を**使用しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを**使用すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。なぜなら、宣言的フレンドリーなツールはそれらをどう扱うべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作など、めったに使用されず本質的に命令的な操作であり、宣言的サポートが期待されないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作を行うカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータが必要である。この規約により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSourcesなど）でファーストクラスの概念を持ち、実行時の影響のリスクなしにどのメソッドを呼び出せるかをユーザーに明確に示す。

`GET` で行われるはずのリクエストに `POST` の使用を許可することは便宜である：

- URLサイズ制限に違反するリクエストにつながる大きなクエリ文字列を回避する。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにする、または少なくとも繰り返しフィールドなどに対する複雑なルールの実装を回避できるようにする。
- 通常は単純なRPCであっても、クエリパラメータで表現できない可能性のある複雑な状況のためにデータを含めることを可能にする。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドが使用されているか、メソッドが明確な動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに `author` フィールドを検索次元として持つ `SearchBooks` を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

"async" という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用されている。この同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象レベルにある。RPC名自体に "async" を使用すると混乱を招き、一部の言語でRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
