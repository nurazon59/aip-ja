# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙をユーザーの意図に沿わせる手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に捻じ曲げるのは良い考えでは _ない_。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される:

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は、動詞の後に名詞を続けたものと**すべきである**（should）。
  - メソッド名には前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - メソッド名に含まれる動詞は、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含む**べきではない**（should not）。
  - メソッド名に `Async` という語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別する目的であれば、接尾辞 `LongRunning` をこの目的で使用**してもよい**（may）。例えば、long-runningな書籍作成RPCを作成する場合（標準の `CreateBook` メソッドがlong-runningの側面を考慮する前に設計された場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）:
  - `GET` は、データやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST` は、リクエストペイロードがURLサイズの制限を超える可能性があり、そのために `body` が必要となる場合、データ取得メソッドに使用**してもよい**（may）。
  - `POST` は、メソッドに副作用がある場合や、リソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIでは、`:` 文字に続けてカスタム動詞（上記の例では `:archive`）を使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` **とすべきである**（should）。
  - 詳細については[HTTPとgRPCトランスコーディング][transcoding]を参照。
- カスタムメソッドは、RPC名に `Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。

### リソースベースのカスタムメソッド

カスタムメソッドは、APIがそのようにモデル化できる場合、リソースに対して動作**しなければならない**（must）:

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` で、かつURIパス内で唯一の変数**でなければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して動作するが、一部のカスタムメソッドは代わりにコレクションに対して動作**してもよい**（may）:

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` で、かつURIパス内で唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に _ステートレス_ である。リクエストを受け取ってレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URIでは、動詞と名詞の両方を `:` セパレータの後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URIに「擬似コレクションキー」を置くことは避ける）。例えば、`:translateText` は `text:translate` よりも好ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを採用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的フレンドリーなカスタムメソッドを除く）。宣言的フレンドリーなツールは、それらに対して何をすべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作など、ほとんど使用されない基本的に命令的な操作であり、宣言的サポートの期待がないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースやコレクションに対して動作するカスタムメソッドは、操作対象のリソースを示すために `name` または `parent` パラメータを必要とする。この規約により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データを読み取るだけのメソッドは、一部のクライアント（TerraformのDataSources）において第一級の概念を持ち、実行時の影響リスクなしに呼び出せるメソッドをユーザーに明確に示す。

通常であれば `GET` で行われていたリクエストに対して `POST` の使用を許可することは、以下の利便性のためである:

- URLサイズの制限に違反するリクエストにつながる大きなクエリ文字列を回避できる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できる。少なくとも、repeatedフィールドなどのための複雑なルールの実装を回避できる。
- 通常は単純なRPCであっても、クエリパラメータで表現できないような複雑な状況に対応するデータを含められる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドを使用しているか、または別の動詞を使用すべきであることを示す。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合は、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索ディメンションとして `author` フィールドを持つ `SearchBooks` を検討する。これにより、過度に特化したメソッドが急増してAPIサーフェスとクライアントサーフェスが肥大化し、APIの管理と利用の両方に複雑さが加わるのを防ぐ。

### RPC名

「async」という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用される。この同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こすことさえある。
