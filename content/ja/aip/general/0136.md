# カスタムメソッド

リソース指向設計（AIP-121）では、カスタムメソッドを使用して、標準メソッドだけではモデル化が困難な任意のアクションを表現する手段を提供する。カスタムメソッドは、APIの語彙がユーザーの意図に準拠するための手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に歪めるのは良い考えでは*ない*。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞の後に名詞が続くものである**べきである**（should）。
  - 名前に前置詞（「for」、「with」など）を含め**てはならない**（must not）。
  - 名前の動詞には、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**るべきではない**（should not）。
  - 名前に`Async`という用語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別することを意図している場合、この目的のためにサフィックス`LongRunning`を使用**してもよい**（may）。例えば、標準の`CreateBook`メソッドがlong-runningの側面が考慮される前に設計された場合に、long-runningの書籍作成RPCを作成するには、カスタムの`CreateBookLongRunning`メソッドを導入できる。
- HTTPメソッドは`GET`または`POST`**でなければならない**（must）：
  - `GET`は、データやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST`は、リクエストペイロードがURLサイズの制限を超える可能性があり、`body`が必要になる場合に、データ取得メソッドに使用**してもよい**（may）。
  - `POST`は、メソッドが副作用を持つか、リソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、`:`文字の後にカスタム動詞（上記の例では`:archive`）を続けて使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase`を使用**しなければならない**（must）。
- `google.api.http`アノテーションの`body`句は`"*"`である**べきである**（should）。
  - 詳細については[HTTPとgRPCトランスコーディング][transcoding]を参照。
- カスタムメソッドは、RPC名に`Request`サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に`Response`サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIがそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは`name`と呼ば**なければならず**（must）、URIパス内で唯一の変数でなければならない。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、一部のカスタムメソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは`parent`と呼ば**なければならず**（must）、URIパス内で唯一の変数でなければならない。
- コレクションキー（上記の例では`books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられていない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようにプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前にする**べきである**（should）。単語の区切りが必要な場合は、`snake_case`を使用**しなければならない**（must）。
- URIは、`:`区切りの後に動詞と名詞の両方を配置する**べきである**（この場合、コレクションが存在しないため、URIに「疑似コレクションキー」を使わない）。例えば、`:translateText`は`text:translate`よりも望ましい。
- ステートレスメソッドは、課金を伴う場合に`POST`を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで議論されている特定の宣言的フレンドリーなカスタムメソッドを除く）。なぜなら、宣言的フレンドリーなツールはそれらをどう扱うべきかを自動的に判断できないからである。

この例外は、`Move`や`Rename`操作のような、めったに使用されない基本的に命令的な操作であり、宣言的サポートの期待がない場合である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示す`name`または`parent`パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET`と`POST`の両方のHTTP動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念として扱われ、実行時の影響のリスクなしにどのメソッドを呼び出せるかをユーザーに明確に示す。

`GET`を使用するはずのリクエストに`POST`の使用を許可することは、便宜上の措置である：

- URLサイズの制限に違反するリクエストにつながる大きなクエリ文字列を回避する。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにするか、少なくとも繰り返しフィールドなどの複雑なルールを実装する必要を回避する。
- 通常は単純なRPCでも、クエリパラメータでは表現できない可能性のあるデータを複雑な状況向けに含められるようにする。

### 前置詞の禁止

一般的に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加するべきところで新しいメソッドが使用されているか、メソッドが別の動詞を使用すべきであることを示す。例えば、`CreateBook`メッセージがすでに存在し、`CreateBookFromDictation`の追加を検討している場合は、代わりに`TranscribeBook`メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合は、`GetBookByAuthor`の代わりに、検索ディメンションとして`author`フィールドを持つ`SearchBooks`を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの爆発的な増加を防ぐ。

### RPC名

「async」という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用されている。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語でRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリで問題を引き起こす可能性さえある。
