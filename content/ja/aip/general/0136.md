# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に準拠する手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能に対してのみ使用**すべきである**（should）。可能な限り標準メソッドを優先すること。これは、標準メソッドの一貫したセマンティクスによる。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動かす」ために無理に変形させるのは良い考え*ではない*。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作するカスタムメソッドを示している。カスタムメソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは、これら3つのケースすべてに適用される。

- メソッドの名前は動詞に名詞が続く形式**すべきである**（should）。
  - 名前には前置詞（"for"、"with"など）を含めて**はならない**（must not）。
  - 名前に含まれる動詞は、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**てはならない**（must not）。
  - 名前に `Async` という用語を含めて**はならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する意図がある場合、サフィックス `LongRunning` をこの目的に使用**してもよい**（may）。例えば、標準の `CreateBook` メソッドが長時間実行の側面を考慮する前に設計された場合に、長時間実行を伴う書籍作成RPCを作成するには、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - `GET` は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST` は、リクエストペイロードがURLサイズ制限を超える可能性があり、そのために `body` が必要な場合、データ取得メソッドに使用**してもよい**（may）。
  - `POST` は、メソッドが副作用を持つ場合やリソースまたはデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIは、カスタム動詞の前に `:` 文字を使用**しなければならず**（must）（上記の例では `:archive`）、URI内の動詞はRPCの名前の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` **とすべきである**（should）。
  - 詳細については [HTTP と gRPC Transcoding][transcoding] を参照。
- カスタムメソッドは、RPC名に `Request` サフィックスを付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` サフィックスを付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースを操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

カスタムメソッドは、APIがそのようにモデル化できる場合、リソースに対して操作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼ば**なければならず**（must）、URIパス内の唯一の変数でなければならない。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、一部のカスタムメソッドは代わりにコレクションに対して操作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ば**なければならず**（must）、URIパス内の唯一の変数でなければならない。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられていない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに対して永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようにプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URIは、`:` 区切り文字の後に動詞と名詞の両方を配置**すべきである**（should）（この場合、コレクションが存在しないため、URI内に「偽のコレクションキー」を置かないこと）。例えば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合、`POST` を使用**しなければならない**（must）。

### 宣言的クライアントフレンドリーなリソース

宣言的クライアントフレンドリーなリソースは通常、カスタムメソッドを採用**すべきではない**（should not）（他のAIPで説明されている特定の宣言的クライアントフレンドリーなカスタムメソッドを除く）。なぜなら、宣言的フレンドリーなツールは、それらに対して何をすべきかを自動的に判断できないからである。

この例外は、`Move` や `Rename` 操作のような、ほとんど使用されない根本的に命令的な操作であり、宣言的サポートが期待されない場合である。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示す `name` または `parent` パラメータを必要とする。この規約により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSourcesなど）においてファーストクラスの概念を持ち、ユーザーに対して、ランタイムへの影響リスクなしに呼び出せるメソッドを明確に示す。

通常は `GET` で行われるリクエストに `POST` の使用を許可するのは、便宜のためである：

- URLサイズ制限に違反するような大きなクエリ文字列を避けることができる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるか、少なくとも繰り返しフィールドなどに対する複雑なルールの実装を回避できる。
- 通常は単純なRPCであっても、クエリパラメータで表現できないデータを含む複雑な状況に対応できる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、新しいメソッドを作成する代わりに既存のメソッドにフィールドを追加すべきか、またはメソッドが別の動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索ディメンションとして `author` フィールドを持つ `SearchBooks` を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの爆発的増加を防ぐことができる。

### RPC名

「async」という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用される。その同期／非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
