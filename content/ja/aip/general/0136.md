# カスタム メソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が困難な任意のアクションを表現する手段として、カスタム メソッドを使用する。カスタム メソッドは、API の語彙がユーザーの意図に準拠する手段を提供するため重要である。

## ガイダンス

カスタム メソッドは、標準メソッドで容易に表現できない機能に対してのみ使用**すべきである**（should）。可能であれば、一貫したセマンティクスを持つ標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に歪めるのは*良くない*考えである。）

カスタム メソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して動作するカスタム メソッドを示している。カスタム メソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞の後に名詞を続ける形に**すべきである**（should）。
  - 名前に前置詞（"for"、"with" など）を含め**てはならない**（must not）。
  - 名前の動詞に標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**てはならない**（must not）。
  - 名前に `Async` という用語を含め**てはならない**（must not）。代わりに、即時 RPC と long-running RPC を区別することを意図している場合、この目的のために接尾辞 `LongRunning` を使用**してもよい**（may）。例えば、long-running な書籍作成 RPC を作成する場合（標準 `CreateBook` メソッドが long-running の側面が検討される前に設計されていた場合）、カスタム `CreateBookLongRunning` メソッドを導入できる。
- HTTP メソッドは `GET` または `POST` **でなければならない**（must）：
  - データやリソースの状態を取得するメソッドには `GET` を使用**しなければならない**（must）。
  - リクエストペイロードが URL サイズ制限を超える可能性があり、そのため `body` が必要となる場合、データ取得メソッドに `POST` を使用**してもよい**（may）。
  - メソッドが副作用を持つ場合や、リソースやデータを変更する場合は `POST` を使用**しなければならない**（must）。
- HTTP URI は `:` 文字の後にカスタム動詞（上記の例では `:archive`）を続ける形に**しなければならず**（must）、URI 内の動詞は RPC の名前の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` に**すべきである**（should）。
  - 詳細については [HTTP と gRPC トランスコーディング][transcoding] を参照。
- カスタム メソッドは、RPC 名に `Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタム メソッドは、RPC 名に `Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して動作する場合、カスタム メソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタム メソッド

API がリソースとしてモデル化できる場合、カスタム メソッドはリソースに対して動作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と**しなければならず**（must）、URI パス内の唯一の変数でなければならない。

### コレクションベースのカスタム メソッド

ほとんどのカスタム メソッドは単一のリソースに対して動作するが、一部のカスタム メソッドは代わりにコレクションに対して動作**してもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と**しなければならず**（must）、URI パス内の唯一の変数でなければならない。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタム メソッドはリソースにまったく結びつかない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API 内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URI は `:` 区切りの後に動詞と名詞の両方を配置**すべきである**（should）（この場合、コレクションがないため、URI 内で「疑似コレクションキー」を使用しない）。例えば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合 `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタム メソッドを使用**すべきではない**（should not）（他の AIP で説明されている特定の宣言的フレンドリーなカスタム メソッドを除く）。宣言的フレンドリーなツールは、それらをどう処理すべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作のような、まれにしか使用されず根本的に命令的な操作であり、宣言的サポートの期待がないものである。

## 根拠

### HTTP パス

標準メソッドと同様に、リソースやコレクションに対して動作するカスタム メソッドは、操作対象のリソースを示す `name` または `parent` パラメータを必要とする。この慣習により、クライアントはカスタム メソッドを適切なリソースにマッピングできる。

### HTTP メソッド

`GET` と `POST` の両方の HTTP 動詞を許可することで、どのメソッドがデータを変更せず、どのメソッドが変更するかを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（Terraform の DataSources など）で第一級の概念を持ち、ランタイムへの影響リスクなしに呼び出せるメソッドをユーザーに明確に示す。

`GET` で行われるはずのリクエストに `POST` を使用できることは、便宜である：

- 大きなクエリ文字列が URL サイズ制限に違反するリクエストを引き起こすことを回避する。
- クライアントがリクエストデータをシリアル化する単一の方法を実装できるようにする。少なくとも、repeated フィールドなどの複雑なルールを実装する必要を回避する。
- 通常は単純な RPC であっても、クエリパラメータでは表現できない可能性のあるデータを複雑な状況のために含めることを可能にする。

### 前置詞の禁止

一般的に、名前に前置詞を含むメソッドは、既存のメソッドにフィールドを追加すべき箇所で新しいメソッドが使用されているか、またはメソッドに別個の動詞を使用すべきことを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索次元として `author` フィールドを持つ `SearchBooks` を検討する。これにより、API およびクライアントサーフェスを肥大化させ、API の管理と利用の両方に複雑さを加える、過度に特化したメソッドの爆発的増加を防ぐことができる。

### RPC 名

「async」という用語は、RPC の実行を含め、特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用されている。その同期/非同期の側面は、RPC 自体が long-running operation を開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC 名自体に「async」を使用すると混乱を招き、一部の言語では RPC を呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
