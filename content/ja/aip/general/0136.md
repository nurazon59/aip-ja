# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドを使用する。カスタムメソッドは、APIの語彙がユーザーの意図に沿うための手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドでは容易に表現できない機能に対してのみ使用**すべきである**（should）。標準メソッドの一貫したセマンティクスのため、可能であれば標準メソッドを優先する。（もちろん、これは問題となる機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために物事を歪めるのは良い考えでは*ない*。）

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作を行うカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、サービスのいずれにも関連付けることができる。以下の箇条書きは3つのケースすべてに適用される。

- メソッド名は動詞の後に名詞を続けたものに**すべきである**（should）。
  - 名前に前置詞（「for」「with」など）を含め**てはならない**（must not）。
  - 名前の動詞に、標準メソッドの動詞（[取得][Get]、[一覧取得][List]、[作成][Create]、[更新][Update]、[削除][Delete]）を含める**べきではない**（should not）。
  - 名前に `Async` という語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する意図がある場合は、接尾辞 `LongRunning` をこの目的で使用**してもよい**（may）。たとえば、長時間実行の書籍作成RPCを作成する場合（標準の `CreateBook` メソッドが長時間実行の側面を考慮する前に設計されていた場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` で**なければならない**（must）：
  - `GET` は、データやリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - `POST` は、リクエストペイロードがURLサイズの制限を超える可能性があり `body` が必要となる場合に、データ取得メソッドに使用**してもよい**（may）。
  - `POST` は、メソッドに副作用がある場合やリソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URI は `:` 文字の後にカスタム動詞（上記の例では `:archive`）を続け**なければならない**（must）。また、URI 内の動詞は RPC 名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` に**すべきである**（should）。
  - 詳細については [HTTPとgRPCトランスコーディング][transcoding] を参照。
- カスタムメソッドは、RPC名に `Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に `Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作を行う場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIをそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作を行わ**なければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼ばれ、URI パス内の唯一の変数で**なければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作を行うが、一部のカスタムメソッドは代わりにコレクションに対して操作を行っ**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ばれ、URI パス内の唯一の変数で**なければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラルで**なければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取りレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URI では、動詞と名詞の両方を `:` 区切りの後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URI 内の「疑似的なコレクションキー」は避ける）。たとえば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を使用**しなければならない**（must）。

### 宣言的クライアント向けリソース

宣言的クライアント向けのリソースは通常、カスタムメソッドを使用**すべきではない**（should）（他のAIPで説明されている特定の宣言的クライアント向けカスタムメソッドを除く）。宣言的クライアント向けツールは、カスタムメソッドに対して何をすべきかを自動的に判断できないためである。

例外として、`Move` や `Rename` 操作のような、まれにしか使用されず本質的に命令的な操作については、宣言的サポートの期待がないため、この限りではない。

## 理論的根拠

### HTTPパス

標準メソッドと同様に、リソースやコレクションに対して操作を行うカスタムメソッドには、操作対象のリソースを示す `name` または `parent` パラメータが必要である。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方の HTTP 動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念として扱われ、実行時の影響のリスクなしに呼び出せるメソッドをユーザーに明確に示す。

`GET` を使用して行うリクエストに `POST` を使用できるようにすることは、便宜上の措置である：

- 大きなクエリ文字列がURLサイズ制限に違反するリクエストを回避できる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できる。少なくとも、repeatedフィールドなどの複雑なルールを実装する必要がなくなる。
- 通常は単純なRPCであっても、クエリパラメータでは表現できない複雑な状況のデータを含められる。

### 前置詞の禁止

一般に、名前に前置詞を含むメソッドは、既存のメソッドにフィールドを追加すべき箇所で新しいメソッドが使用されているか、メソッドに別の動詞を使用すべきであることを示す。たとえば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` ではなく、`author` フィールドを検索ディメンションとして持つ `SearchBooks` を検討する。これにより、APIとクライアントのサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを加える過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

「async」という用語は、RPCの作成を含め、特定のメソッド呼び出しが同期的か非同期的かを示すためにプログラミング言語で一般的に使用される。その同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリで問題を引き起こす可能性さえある。
