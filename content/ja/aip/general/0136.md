# カスタムメソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が難しい任意のアクションを表現する手段として、カスタムメソッドが使用される。カスタムメソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため重要である。

## ガイダンス

カスタムメソッドは、標準メソッドで容易に表現できない機能に対してのみ使用**すべきである**（should）。一貫したセマンティクスを持つ標準メソッドを可能な限り優先すること。（もちろん、これは問題の機能が実際に通常のセマンティクスに準拠する場合にのみ適用される。標準メソッドが「なんとか動作する」ように無理に変形させるのは良い考えでは_ない_）。

カスタムメソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される。

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは、特定のリソースに対して操作するカスタムメソッドを示している。カスタムメソッドは、リソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きは、これら3つのケースすべてに適用される。

- メソッド名は、動詞に名詞を続けたものと**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前に使用する動詞は、標準メソッドの動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）のいずれも含む**べきではない**（should not）。
  - 名前に `Async` という用語を含め**てはならない**（must not）。代わりに、即時RPCと長時間実行RPCを区別する目的がある場合、その目的のために接尾辞 `LongRunning` を使用**してもよい**（may）。例えば、長時間実行の書籍作成RPCを作成する場合（標準の `CreateBook` メソッドが長時間実行の側面を考慮する前に設計されていた場合）、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` で**なければならない**（must）：
  - `GET` は、データまたはリソースの状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、`body` が必要となる場合、`POST` をデータ取得メソッドに使用**してもよい**（may）。
  - メソッドが副作用を持つか、リソースやデータを変更する場合、`POST` を使用**しなければならない**（must）。
- HTTP URIでは、`:` 文字に続けてカスタム動詞（上記の例では `:archive`）を使用**しなければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は、`camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` と**すべきである**（should）。
  - 詳細については [HTTP and gRPC Transcoding][transcoding] を参照。
- カスタムメソッドは、RPC名に一致し、`Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタムメソッドは、RPC名に一致し、`Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して操作する場合、カスタムメソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタムメソッド

APIをそのようにモデル化できる場合、カスタムメソッドはリソースに対して操作**しなければならない**（must）。

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と呼ば**れなければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。

### コレクションベースのカスタムメソッド

ほとんどのカスタムメソッドは単一のリソースに対して操作するが、代わりにコレクションに対して操作し**てもよい**（may）ものもある。

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と呼ば**れなければならず**（must）、URIパス内の唯一の変数で**なければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラルで**なければならない**（must）。

### ステートレスメソッド

一部のカスタムメソッドは、リソースにまったく関連付けられていない。これらのメソッドは一般に_ステートレス_であり、リクエストを受け取ってレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例のようなプロジェクトなど）で実行される場合、リクエストメッセージ内のフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は、`snake_case` を使用**しなければならない**（must）。
- URIでは、動詞と名詞の両方を `:` 区切り文字の後に配置**すべきである**（should）（この場合、コレクションが存在しないため、URIに「擬似コレクションキー」を含めない）。例えば、`:translateText` が `text:translate` よりも望ましい。
- ステートレスメソッドは、課金を伴う場合に `POST` を使用**しなければならない**（must）。

### 宣言的フレンドリーなリソース

宣言的フレンドリーなリソースは通常、カスタムメソッドを使用**すべきではない**（should not）（他のAIPで議論されている特定の宣言的フレンドリーなカスタムメソッドを除く）。なぜなら、宣言的フレンドリーなツールは、それらをどう処理すべきかを自動的に判断できないためである。

この例外は、`Move` や `Rename` 操作のような、ほとんど使用されず根本的に命令的な操作であり、宣言的サポートの期待がないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して操作するカスタムメソッドは、操作対象のリソースを示す `name` または `parent` パラメータを必要とする。この規則により、クライアントはカスタムメソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、実行時の影響リスクなしに呼び出せるメソッドをユーザーに明確に示す。

通常であれば `GET` を使用するリクエストに `POST` を使用できることは、利便性のためである：

- URLサイズ制限に違反するリクエストにつながる大きなクエリ文字列を回避できる。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できる。少なくとも、repeatedフィールドなどの複雑なルールを実装する必要がなくなる。
- 通常は単純なRPCであっても、クエリパラメータでは表現できないデータを含む複雑な状況に対応できる。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、既存のメソッドにフィールドを追加すべきところで新しいメソッドを使用しているか、または異なる動詞を使用すべきであることを示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索ディメンションとして `author` フィールドを持つ `SearchBooks` を検討する。これにより、APIおよびクライアントのサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する、過度に特化したメソッドの爆発を防ぐことができる。

### RPC名

"async"という用語は、RPCの実行を含め、特定のメソッド呼び出しが同期的か非同期的かを示すために、プログラミング言語で一般的に使用されている。その同期/非同期の側面は、RPC自体が長時間実行オペレーションを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に"async"を使用すると混乱を招き、一部の言語ではRPCを呼び出すための同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こす可能性さえある。
