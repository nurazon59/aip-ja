# カスタム メソッド

リソース指向設計（AIP-121）では、標準メソッドだけではモデル化が困難な任意のアクションを表現する手段としてカスタム メソッドを用いる。カスタム メソッドは、APIの語彙をユーザーの意図に適合させる手段を提供するため重要である。

## ガイダンス

カスタム メソッドは、標準メソッドでは容易に表現できない機能にのみ使用**すべきである**（should）。一貫したセマンティクスを持つため、可能であれば標準メソッドを優先する。（もちろん、これは問題の機能が実際に通常のセマンティクスに適合する場合にのみ適用される。標準メソッドを「なんとか動作させる」ために無理に歪めるのは良い考えでは*ない*。）

カスタム メソッドの設計方法は多岐にわたるが、多くの原則が一貫して適用される：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

**注:** 上記のパターンは特定のリソースに対して動作するカスタム メソッドを示している。カスタム メソッドはリソース、コレクション、またはサービスに関連付けることができる。以下の箇条書きはこれら3つのケースすべてに適用される。

- メソッド名は動詞に名詞が続く形に**すべきである**（should）。
  - 名前に前置詞（"for"、"with"など）を含め**てはならない**（must not）。
  - 名前の動詞に標準メソッド動詞（[Get][]、[List][]、[Create][]、[Update][]、[Delete][]）を含め**るべきではない**（should not）。
  - 名前に `Async` という語を含め**てはならない**（must not）。代わりに、即時RPCとlong-running RPCを区別することが目的である場合、接尾辞 `LongRunning` をこの目的で使用**してもよい**（may）。例えば、標準の `CreateBook` メソッドがlong-runningの側面が考慮される前に設計された場合に、long-runningな書籍作成RPCを作成するには、カスタムの `CreateBookLongRunning` メソッドを導入できる。
- HTTPメソッドは `GET` または `POST` **でなければならない**（must）：
  - `GET` はデータまたはリソース状態を取得するメソッドに使用**しなければならない**（must）。
    - リクエストペイロードがURLサイズ制限を超える可能性があり、そのため `body` が必要となる場合、`POST` をデータ取得メソッドに使用**してもよい**（may）。
  - `POST` はメソッドに副作用があるか、リソースやデータを変更する場合に使用**しなければならない**（must）。
- HTTP URIでは `:` 文字の後にカスタム動詞（上記の例では `:archive`）を続け**なければならず**（must）、URI内の動詞はRPC名の動詞と一致**しなければならない**（must）。
  - 単語の区切りが必要な場合は `camelCase` を使用**しなければならない**（must）。
- `google.api.http` アノテーションの `body` 句は `"*"` に**すべきである**（should）。
  - 詳細については [HTTP and gRPC Transcoding][transcoding] を参照。
- カスタム メソッドは、RPC名に `Request` 接尾辞を付けたリクエストメッセージを受け取る**べきである**（should）。
- カスタム メソッドは、RPC名に `Response` 接尾辞を付けたレスポンスメッセージを返す**べきである**（should）。
  - 特定のリソースに対して動作する場合、カスタム メソッドはリソース自体を返し**てもよい**（may）。


### リソースベースのカスタム メソッド

APIをリソースとしてモデル化できる場合、カスタム メソッドはリソースに対して動作**しなければならない**（must）：

```proto
// Archives the given book.
rpc ArchiveBook(ArchiveBookRequest) returns (ArchiveBookResponse) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:archive"
    body: "*"
  };
}
```

- リソース名のパラメータは `name` と**呼ばなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。

### コレクションベースのカスタム メソッド

ほとんどのカスタム メソッドは単一のリソースに対して動作するが、一部のカスタム メソッドは代わりにコレクションに対して動作し**てもよい**（may）：

```proto
// Sorts the books from this publisher.
rpc SortBooks(SortBooksRequest) returns (SortBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:sort"
    body: "*"
  };
}
```

- コレクションのリソースに親がある場合、そのリソースは `parent` と**呼ばなければならず**（must）、URIパス内の唯一の変数**でなければならない**（must）。
- コレクションキー（上記の例では `books`）はリテラル**でなければならない**（must）。

### ステートレスメソッド

一部のカスタム メソッドはリソースにまったく結びつかない。これらのメソッドは一般に*ステートレス*である：リクエストを受け取ってレスポンスを返し、API内のデータに永続的な影響を与えない。

```proto
// Translates the provided text from one language to another.
rpc TranslateText(TranslateTextRequest) returns (TranslateTextResponse) {
  option (google.api.http) = {
    post: "/v1/{project=projects/*}:translateText"
    body: "*"
  };
}
```

- メソッドが特定のスコープ（上記の例ではプロジェクトなど）で実行される場合、リクエストメッセージのフィールド名はスコープリソースの名前に**すべきである**（should）。単語の区切りが必要な場合は `snake_case` を使用**しなければならない**（must）。
- URIでは、`:` 区切り文字の後に動詞と名詞の両方を置く**べきである**（この場合、コレクションが存在しないため、URIに「偽のコレクションキー」を置くのは避ける）。例えば、`:translateText` は `text:translate` よりも望ましい。
- ステートレスメソッドが課金を伴う場合は `POST` を使用**しなければならない**（must）。

### 宣言的クライアントフレンドリーなリソース

宣言的クライアントフレンドリーなリソースは通常、カスタム メソッドを採用**すべきではない**（should not）（他のAIPで議論されている特定の宣言的クライアントフレンドリーなカスタム メソッドを除く）。これは、宣言的クライアントフレンドリーなツールがそれらを自動的にどう処理すべきかを判断できないためである。

これに対する例外は、`Move` や `Rename` 操作のような、まれにしか使用されない基本的に命令的な操作であり、宣言的サポートの期待がないものである。

## 根拠

### HTTPパス

標準メソッドと同様に、リソースまたはコレクションに対して動作するカスタム メソッドは、操作対象のリソースを示すために `name` または `parent` パラメータを必要とする。この規約により、クライアントはカスタム メソッドを適切なリソースにマッピングできる。

### HTTPメソッド

`GET` と `POST` の両方のHTTP動詞を許可することで、データを変更しないメソッドと変更するメソッドを明確に区別できる。データの読み取りのみを行うメソッドは、一部のクライアント（TerraformのDataSources）で第一級の概念を持ち、実行時への影響のリスクなしに呼び出せるメソッドをユーザーに明確に示す。

`POST` を、他の方法では `GET` を使用するようなリクエストに使用できるようにすることは便宜である：

- URLサイズ制限に違反するような大きなクエリ文字列を回避する。
- クライアントがリクエストデータをシリアライズする単一の方法を実装できるようにし、少なくとも繰り返しフィールドなどのための複雑なルールの実装を回避する。
- 通常は単純なRPCでも、クエリパラメータで表現できない複雑な状況のためのデータを保持できるようにする。

### 前置詞の禁止

一般に、前置詞を含むメソッド名は、新しいメソッドを使用する代わりに既存のメソッドにフィールドを追加すべき場所、またはメソッドに別の動詞を使用すべき場所を示している。例えば、`CreateBook` メッセージが既に存在し、`CreateBookFromDictation` の追加を検討している場合、代わりに `TranscribeBook` メソッドを検討する。同様に、プロパティ固有の検索メソッドが必要な場合、`GetBookByAuthor` の代わりに、検索次元として `author` フィールドを持つ `SearchBooks` を検討する。これにより、APIとクライアントサーフェスを肥大化させ、APIの管理と利用の両方に複雑さを追加する過度に特化したメソッドの爆発的な増加を防ぐことができる。

### RPC名

「async」という用語は、RPCを含む特定のメソッド呼び出しが同期か非同期かを示すためにプログラミング言語で一般的に使用されている。この同期/非同期の側面は、RPC自体がlong-running operationを開始することを意図しているかどうかとは異なる抽象化レベルにある。RPC名自体に「async」を使用すると混乱を招き、一部の言語ではRPCを呼び出すために同期メソッドと非同期メソッドの両方を生成するクライアントライブラリに問題を引き起こすことさえある。
